# Visual Ancestry v0.3 Phase 2.1 — 自动探索闭环修复

日期：2026-10-21 ｜ 分支：`develop/v0.3-visual-explore` ｜ 基线：`24bb399`

本轮修的是 Phase 2 留下的四个断点：远端作品只能看不能走、分支语义把"近邻"说成"同风格"、补货没有真正的自动触发、媒介筛选会把外部结果清掉。

---

## 一、连续探索：远端作品是作品节点，不是外链

- 新增内部路由 `#artwork/r.<图片哈希>`，复用**同一个** `src/pages/artwork.js`，没有第二套详情系统（`qa/features/p21-explore.test.mjs` 里有用例钉住这一点）。
- 远端详情页从 `/api/discovery/work/<hash>` 取记录：真实图片、来源、权利、发现关键词、实测像素。
- "查看原始馆藏 ↗" 是**独立**链接（`target=_blank`），卡片外层不再是 `<a>`——否则两个目标会互相吞掉。
- 以远端作品为起点可以继续探索：同一个 `/api/discovery/neighbors`，只是把 `artworkId` 换成 `hash`，向量直接读索引，不再算一遍。
- 刷新远端详情页仍可打开（数据在服务端有源，不是内存态）。

实测：`#artwork/local:paris-rainy-day` → 外部候选 → 点击 → `#artwork/r.e5c93fb0…`（Charles Marville《Rue de la Ferronnerie》，Cleveland）→ 该页再次给出 6 条候选。全程 host 未变。

## 二、分支语义：保留 × 变化，两段缺一就不给风格说法

证据由两段组成，服务端算，卡片上分开写：

| 段 | 依据 | 说明 |
|---|---|---|
| 保留 | 像素实测：色温一致、饱和度差、对比度差、平均明度差、边缘密度差、画幅接近 | 至少 3 项通过，且必须有色调类证据；只靠对比度+边缘不算 |
| 变化 | 主体 / 场景 / 构图（画幅、明度重心、对称性） | 来自标题与像素，不是模型结论 |

三档呈现，全部不含"已验证"：

- `待验证的风格延展` — 保留与变化都有证据，但**没有 Vision 确认**；
- `同一视觉语言（主体未变）` — 保留有、变化没检测到；
- `视觉语言证据不足` — 只有变化，像素亲和度不够。

阈值收紧过一次：0.62 → **0.68**，并要求至少 3 项像素证据。原因是 Rijks 的《Four Lidded Vases》（深色器物）以 0.659 混进了"换主体"，这正是假关联。收紧后它被剔除。

分支标题也会跟着改：只要一栏里出现外部候选，标题就从"同风格，换主体"变成"换主体（待验证）"；以远端作品为起点的整页，四条分支从一开始就是中性标题，区块标题写作 **EXPLORE · 更多视觉发现（待验证）**。

一处限制如实说明：外部作品没有档案描述，主体/场景只能从标题或"它是被哪个关键词发现的"判断，后者在证据里标为"来源关键词，强度低于画面描述"。

## 三、按需补货：真触发、去重、可轮询、有限速

**触发**：候选总数 < 8 时，服务端自动入队；页面轮询 `/api/discovery/job/<id>` 并把状态显示在探索区（"候选不足，正在后台补充（采集中）：impressionism city street"），完成后自动重算候选。

**查询词**不是硬编码：从画派 + 主体派生（`impressionism` + `city` → `impressionism city street`）；远端作品没有画派字段时退回它的标题。

**不阻塞请求**：

- 本地作品向量在构建期预生成（`npm run discovery:vectors`，46 件），请求只读 `.rc1-audit/discovery/local-vectors.json`；
- 未预生成的作品返回 `202 vector-pending`，不在请求里跑 Python；
- 抓图与建索引都在后台作业里，串行执行（并发 1），队列上限 6。

**去重与缓存**：同一查询 30 分钟窗口内不重复抓；作业按查询去重；命中缓存返回 `cached:true`。实测第二次请求同一查询：`{"ok":true,"harvested":0,"cached":true,"works":347}`。

**入口保护**（公开部署也成立）：

- 同源校验：跨源 POST 返回 **403**（实测）；
- 每 IP 限速：1 分钟 6 次 / 1 小时 40 次，超限 **429**（实测 burst 出现 429）；
- 可选 `DISCOVERY_TRIGGER_TOKEN`：配置后必须带 `x-discovery-token`；
- 队列满时明确 `queue-full`，不无限排队。

## 四、媒介筛选：一份状态，本地与远端同一口径

- 规则抽到 `src/services/explore/externalMedia.js`，页面与测试共用；黑白阈值沿用 `MONOCHROME_SAT = 0.06`，没有另造一套。
- 切换媒介只重绘分支区，外部候选从 `pageState.external` 重新过滤后插回，**不会丢**。
- 黑白影像不进入电影/动画档；动画档仍为空时给理由，不拿封面或绘画凑数。

实测（本地页）：`all=12（外部 5）→ 绘画=10（外部 3）→ 恢复=12`；（远端页）：`all=6 → 绘画=3 → 恢复=6`；动画档外部 0 条，并写明"本媒介下 0 条，隐藏 6 条"。

## 六、仍然存在的缺口

1. **TMDB 依旧未配置**：电影/剧集剧照、动画单集画面仍为 0，动画档只有空状态。适配器在，但没有凭据就不验收。
2. **远端查询的主体/场景分支常为空**：外部作品没有档案描述，标题短的作品判不出主体，只能落在"换构图/局部视觉语言"。这是证据不足，不是漏做。
3. **阈值偏保守**：收紧后 `paris-rainy-day` 只剩 5 条候选，其中 1 条是"证据不足"。宁可少，也不把器物说成风格延展。
4. **同题跨来源重复**已用"标题归一化（去扩展名、去标点、小写）"过滤，但不同语言标题的同一作品仍可能各自出现一次。
5. **Phase 2 遗留**：Met 主图约 24 张/轮 403；Openverse 匿名配额会 429；LoC 未实现。
