# Frame Atlas v0.4 — 跨媒介视觉质量验收（阶段报告）

日期：2026-10-26/27 ｜ 分支：`develop/v0.4-visual-quality` ｜ 基线 commit：`917264e`（v0.3.0 交付报告）
状态：**开发中（Active Development）**。本报告只提交质量验收结果供审查，不合并 main、不发版、不部署。

---

## 一、结论先说

| 项 | 结论 |
|---|---|
| 阶段目标（独立测试集 Top-5 有效率 ≥ 60%） | **未达到，且未被验证**。48 起点盲评里最好的一档是基线 MobileCLIP-S0 的 **33%（4/12）**；独立测试集上三套编码器 **Top-5 完全一致（一致率 1.00）**，只差内部次序，本轮未对测试集做人工 Top-5 判定，因此不得宣称达标 |
| 换更强编码器是否提升 | **没有提升**。SigLIP-base 17%、CLIP ViT-L/14 33%，均 ≤ 基线 33%；独立测试集上三者取回集合完全相同 |
| 结构相似度重排（v0.3 做法）是否提升 | **没有提升**（33%，Top-5 内「有效」件数 6 vs 基线 7） |
| 因此是否接入现有检索系统 | **不接入**。按指令「只有实验实际证明提升，才最小范围接入」——本轮未证明，故未改产品检索代码 |
| 付费模型调用 | **0 次**。全部用本地 CPU 开源模型（MIT / Apache-2.0 许可），未调用任何付费服务 |
| 48 张跨媒介样本的根因 | **主要不是排序问题，是候选库缺失**：见 §三 |

**这一轮最有价值的结果是负面的**：跨媒介关联弱，主要不是编码器不够强，而是**库里根本没有对应媒介与题材的画面**（动画桶 30 帧里 0 帧赛璐璐、0 帧手绘、0 帧低饱和现实场景）。换编码器在缺素材的池子上不可能变好。

## 二、方法与口径

| 环节 | 做法 |
|---|---|
| 池快照 | `scripts/p416/build-pool.mjs`：发现库索引（553 条，含 512 维向量 + 图像度量）+ 采集元数据（558 条，含许可/来源/本地路径）+ 本地档案 47 条向量 → 605 条 |
| 分桶 | 按采集侧 `imageKind`：painting 327 / film 34 / animation 30 / photo 194 / anime 20 |
| 比较方法 | ① mobileclip（基线，512 维）② siglip-base（768 维）③ clip-large（768 维）④ hybrid = 基线余弦与结构相似度各半（v0.3 做法）⑤ hybrid-siglip = SigLIP 余弦与结构各半 |
| 结构相似度 | 亮度三段分层、左右均衡、画幅、边缘密度、冷暖，共 5 轴（沿用 v0.3 思路，结构度量直接取自池内既有 metrics） |
| 盲评 | 12 起点 × 各方法 Top-5 的**并集**（去重后每张 10–16 件），生成对照图逐件人工判定「有效 / 弱 / 错误」，判定标准沿用 v0.3 |
| 指标 | success@5 = 该方法 Top-5 中至少有一件被判「有效」的起点占比；另报 Top-5 内三档分布 |

**判定者与实现者是同一人**（本轮执行者），这一点如实记录，不当作独立评审。

**公平性修正**：初版对照图的候选并集被先遍历的方法占满，后面的方法没被看到，导致新编码器被系统性漏评。已改为「各方法 Top-5 轮流放入并集」，并把并集上限提到 16 件后重做全部对照图与判定。

## 三、根因分析：候选库缺失 vs 排序错误

把 12 个起点逐个拆开，看「有效的候选到底在不在库里」：

| 路径 | 有效候选是否存在于池中 | 判定 |
|---|---|---|
| 绘画 → 电影 | 存在（雨中人物帧、夜城湿地面、哥特拱门人物） | **排序问题**：基线能取到（有效件落在 Top-3~5）；CLIP-L 在 wave 上把「Collapse of the Funnel」排到 #1（被判有效），基线没取到 |
| 电影 → 绘画 | 存在（雨夜城市街景 Broadway / A rainy night on the city、Monk by the Sea、神奈川冲浪里） | **排序问题，且新编码器更差**：基线把三件有效画作排到 #1~#4；SigLIP / CLIP-L 返回 Eight Bells、Pair of Flintlock Pistols 等弱/错件，success@5 = 0 |
| 绘画 → 动画 | **不存在**。动画桶 30 帧全部是 Big Buck Bunny（blender 20 帧）与 Commons 动画截图（10 帧），内容为卡通/兔子/日式封面 | **库缺失**：雨夜欧洲街道、巨大浪体、正面哥特肖像在动画侧没有任何对应素材 |
| 动画 → 绘画 | 部分存在 | BBB-30s 存在（牧场+树+牲畜的风景画），基线排 #1（有效）；BBB-60s（灰兔仰视特写）与 Billiondollarlimited2（暗室霓虹）**无对应画作** → **库缺失** |

补充的池级事实（同样影响可达上限）：

- 绘画桶 327 件全是 `imageKind=artwork`；电影桶 34 件里 33 帧是 `film-still`；动画桶 30 帧 = blender 20 + commons 10。
- 动画桶**没有一帧**是赛璐璐、手绘动画或低饱和现实场景 —— 这与 v0.3 报告「跨媒介最差是绘画→动画」完全一致，且给出了机制层面的解释。
- 池内存在**同名重复条目**（同一文件被抓两次，如 "Rescued in Mid Air (1906)"、"Tears of Steel — 275s"），会占用 Top-5 名额。本轮实验已按标题去重后排序，**但产品侧尚未去重**（列为待修）。
- 运行时 `mediaTaxonomy.pickMedium()` 对 medium 缺省的条目按 artwork 处理，因此产品实际的「绘画」候选面可能还包含采集侧的 194 张 photograph。**这一点未在产品侧实测，列为待核实**，不在本报告当作结论。

## 四、编码器对比（真实 CPU 推理，非模拟）

| 方案 | 模型 | 许可 | 维度 | 全池 605 张耗时 | success@5 | Top-5 内 有效/弱/错误 |
|---|---|---|---|---|---|---|
| 基线 | `mobileclip_s0_vision_int8`（Apple ml-mobileclip ONNX int8） | MIT | 512 | 既有产物 | **33%（4/12）** | 7 / 36 / 17 |
| 新 | `google/siglip-base-patch16-224` | Apache-2.0 | 768 | 605 张 / 约 2 分钟（5.1 张/秒） | 17%（2/12） | 2 / 43 / 15 |
| 新 | `openai/clip-vit-large-patch14` | MIT | 768 | 605 张 / 约 7 分钟（1.4 张/秒） | 33%（4/12） | 4 / 37 / 19 |
| 重排 | hybrid（基线余弦 + 结构各半） | — | — | 复用基线向量 | 33%（4/12） | 6 / 37 / 17 |
| 重排 | hybrid-siglip（SigLIP 余弦 + 结构各半） | — | — | 复用 SigLIP 向量 | 17%（2/12） | 2 / 45 / 13 |

逐路径 success@5：

| 路径 | mobileclip | siglip-base | clip-large | hybrid | hybrid-siglip |
|---|---|---|---|---|---|
| 绘画 → 电影 | 1/3 | **2/3** | **2/3** | 1/3 | **2/3** |
| 电影 → 绘画 | 1/3 | 0/3 | 1/3 | **2/3** | 0/3 |
| 绘画 → 动画 | 1/3 | 0/3 | 1/3 | 1/3 | 0/3 |
| 动画 → 绘画 | 1/3 | 0/3 | 0/3 | 0/3 | 0/3 |

**读法**：强编码器在「绘画→电影」上略有改善（1/3 → 2/3），但在「电影→绘画」上退化（SigLIP 0/3），在两个动画相关路径上没有任何方法取得好成绩。整体没有超过基线。

**成本**：0 次付费调用；本地 CPU 推理；磁盘新增 = 两个开源模型权重（SigLIP ≈ 0.4 GB、CLIP-L ≈ 1.7 GB，均在 HuggingFace 公共仓库，可删除）。

## 六、独立测试集（授权合规）

采集脚本 `scripts/p416/harvest-testset.mjs`：Wikimedia Commons，**逐件核验文件页 `extmetadata` 的许可**，只保留 Public domain / CC0 / CC BY / CC BY-SA / PDM；**BY-NC / BY-ND 一律不收**（限制商用与改作，与产品定位冲突）。四个方向的实际采集结果：

| 方向 | 采集来源 | 实收 | 许可构成 | 备注 |
|---|---|---|---|---|
| 赛璐璐 / cel-shaded | 关键词 + `Category:Cel shading`、`Category:Cel-shaded` | **8 件** | Public domain 6、CC BY-SA 1、CC BY 2.5 1 | 分类内多为着色技术示意图，风格代表性有限 |
| 电影化光影 | 关键词 + `Category:Tears of Steel`、`Category:Metropolis (1927 film)` | **0 件** | — | **采集失败，见下方说明** |
| 手工动画 | `Category:Out of the Inkwell Films`、`Category:Winsor McCay films`、`Category:Traditional animation` | **3 件** | Public domain 1、CC BY-SA 1、CC BY-SA 4.0 1 | 公有领域手绘动画多以视频形式存在，位图极少 |
| 绘画构图 | 关键词检索 | **3 件** | Public domain 3 | 命名与构图标签的对应弱，需人工筛 |

**清单字段**：id、方向、标题、文件页 URL、许可、UsageTerms、作者、Credit、原始日期、尺寸、来源途径（search/category）、`visualKind`（frame/poster）、原始 mime。

**「电影化光影」方向采集失败的定位**：直接查询 `Tears of Steel frame filetype:bitmap` 可拿到 `File:Tears of Steel frame 09 1a.jpg`（image/jpeg、3840×1600、**CC BY 3.0**），许可与尺寸都合格；但采集流程枚举到该方向时得到 0 个候选，且日志无异常。逐项排除后的结论是**候选枚举环节的问题（分类名很可能不对，关键词路径未生效）**，不是许可过滤或尺寸过滤。已列为待修项，未在本轮强行绕过。

**测试集上的客观度量**（14 件、28 个跨方向查询-目标对，三套编码器各算一遍）：

| 指标 | 结果 |
|---|---|
| Top-5 一致率：clip-large vs mobileclip | **1.00** |
| Top-5 一致率：mobileclip vs siglip-base | **1.00** |
| Top-5 一致率：clip-large vs siglip-base | **1.00** |

也就是说：在这个风格高度一致的独立测试集上，**三套编码器返回的 Top-5 完全相同，只有内部次序不同**（例如 cel→handdrawn，基线把 `File-Inkandpaint.jpg` 排第一，SigLIP / CLIP-L 把 `Lotte Reiniger Prinz Achme` 排第一）。这条结果本身说明：**换编码器在这个素材规模下不改变「取回什么」，只改变「排谁在前」**，而次序差异需要人工判定才能判断优劣——本轮未对测试集做人工 Top-5 判定（样本规模与预算受限），因此**「独立测试集 Top-5 有效率 ≥ 60%」这一目标未被验证**，不得据此宣称达标。

可核查证据（随本 commit 提交）：
`docs/p2/evidence/v04/` 下 `blind-judgements.json`（48 样本逐格判定）、`metrics-48sample.json`（各方法 success@5 与分布）、`testset-manifest.json`（测试集逐件许可）、`sheets-index.json`（对照图索引与各方法名次）。

**采集规模受 Commons 内容形态限制**（公有领域手绘动画与赛璐璐多为视频文件），未达到每方向 10 件以上；这一限制如实记录，不掩饰。

## 九、复现

```bash
# 0. 环境（工作区内独立目录，避免污染系统 site-packages）
pip install --target .rc1-audit/p416/pylibs torch transformers onnxruntime sentencepiece

# 1. 池快照
node scripts/p416/build-pool.mjs .

# 2. 三套向量（本地 CPU，无付费调用）
PYTHONPATH=.rc1-audit/p416/pylibs python scripts/p416/embed.py \
  --model google/siglip-base-patch16-224 --pool .rc1-audit/p416/pool.json \
  --out .rc1-audit/p416/emb-siglip-base.json
PYTHONPATH=.rc1-audit/p416/pylibs python scripts/p416/embed.py \
  --model openai/clip-vit-large-patch14 --pool .rc1-audit/p416/pool.json \
  --out .rc1-audit/p416/emb-clip-large.json
PYTHONPATH=.rc1-audit/p416/pylibs python scripts/p414/embed.py \
  --manifest .rc1-audit/p416/pool.json --out .rc1-audit/p416/emb-mobileclip.json

# 3. 排序 → 对照图 → 判定 → 指标
node scripts/p416/rank.mjs .
python scripts/p416/make-sheets.py .
node scripts/p416/score.mjs .

# 4. 独立测试集
node scripts/p416/harvest-testset.mjs .
node scripts/p416/build-testset-pool.mjs .
node scripts/p416/rank-testset.mjs .
```
