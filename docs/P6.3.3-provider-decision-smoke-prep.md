### 2.5 请求数与 attempts 统计（D14）

| 项 | 口径 |
|---|---|
| client 请求数 | **1 / 资产**（harness 无重试逻辑）|
| provider attempts | 由延迟推断：`latencyMs ≤ 60000` → 1；`> 60000` → 2（bridge 每尝试 60s 超时，瞬态自动重试 1 次）；无响应 → `null`（不猜测）|
| attempts > 2 | 视为异常（多层重试迹象，需排查）—— 本 harness 每资产最多 1 client 请求 × bridge 2 attempts = **2** |
| 记录字段 | `clientRequests` / `providerAttempts` / `attemptsBasis` 已写入 `provider-smoke.mjs` 输出 |

## STEP 3 · 公网最小架构（READY）

**设计原则**：优先复用现有代码（`scripts/server.mjs` 为唯一服务端），
不引入 Agent、数据库、复杂框架。全部为可独立启用的薄层。

```
                        ┌──────────────────────────────┐
                        │        Frontend Hosting       │
                        │  (Vercel / Netlify / Cloudflare │
                        │   Pages — 静态 dist/ 托管)      │
                        └──────────────┬───────────────┘
                                       │ 同源 /api/vision（同一域名，无 CORS）
                        ┌──────────────▼───────────────┐
                        │        Node Bridge 部署        │
                        │  serverless function (Vercel/  │
                        │  Netlify) 或 1× 小容器          │
                        │  复用 scripts/server.mjs 的    │
                        │  handleVision + validator       │
                        └──────────────┬───────────────┘
                                       │ HTTPS（平台证书）
                        ┌──────────────▼───────────────┐
                        │      Server Env (Secrets)      │
                        │  VISION_API_BASE/KEY/MODEL     │
                        │  (Vercel/Netlify env 面板,      │
                        │   ✓ 不落盘 ✓ 不进 bundle)      │
                        └──────────────┬───────────────┘
                                       │ 服务端→provider
                        ┌──────────────▼───────────────┐
                        │    Upstream Vision Provider    │
                        │    (真实付费 endpoint)         │
                        └──────────────────────────────┘
```

### 3.1 前端托管

| 方案 | 说明 |
|---|---|
| **Vercel / Netlify / Cloudflare Pages（推荐）** | `npm run build` 产出 `dist/`（218 文件，`server/` 永不进入）；静态托管 + 免费 HTTPS 证书 + 全球 CDN |
| 现有 GitHub 私有仓库 | `xiebenzhen-code/visual-archive` 可直接接入 Vercel/Netlify 自动部署 |

### 3.2 Node Bridge 部署

| 方案 | 说明 |
|---|---|
| **Serverless Function（推荐）** | 把 `handleVision` 抽为无状态函数（现有 `scripts/server.mjs` 的 `/api/vision` 分支已是独立 handler，迁移成本 ≈ 包装一层 export）。Vercel `/api/vision.ts` 或 Netlify Function。无服务器、按调用计费、天然扩容 |
| 1× 小容器 | 若需固定 IP/审计，Docker 跑 `scripts/server.mjs`；需要自己处理证书与限流，成本更高 |
| **注意** | `server/` 下的 `openaiProvider.mjs` + `visualIntentValidator.mjs` 必须随函数一起部署（当前 build 不打包它们，需在平台配置额外文件）|

### 3.3 服务端密钥管理

| 项 | 做法 |
|---|---|
| 位置 | 仅平台 env 面板（Vercel/Netlify secrets），**不落盘、不进 git、不进 dist** |
| 边界 | 浏览器永远拿不到 `VISION_API_BASE/KEY/MODEL`；build 泄漏扫描（76 文件 0 违禁）作为 CI 门禁 |
| 轮换 | 平台 env 支持版本化/回滚，密钥吊销即生效 |

### 3.4 用户鉴权（MEA-14）

| 方案 | 说明 |
|---|---|
| **最小：静态访问口令（推荐）** | 前端用 `sessionStorage` 持有口令，`/api/vision` 请求携带 `X-VA-Auth` 头；serverless 校验。个人作品集场景够用，零数据库 |
| 中期：托管身份 | Vercel/Netlify 的社交登录（GitHub OAuth）—— 但会引入身份依赖，非当前必需 |
| 现阶段明确**不做** | 多用户系统、用户表、JWT 自建 —— 与「个人视觉记忆系统」定位不符 |

### 3.5 API 限流与费用上限（MEA-06）

| 层 | 做法 |
|---|---|
| **费用硬上限（最高优先级）** | 平台月度用量告警 + 信用卡硬限额；或 provider 侧账户余额/配额上限。**这是防「一夜烧穿预算」的唯一硬闸** |
| 限流 | serverless 平台自带 per-IP 速率限制（Vercel 可配）；再加应用层计数：`X-VA-Auth` 口令 + 每 IP 每 10 分钟 N 次 |
| 客户端 | 已有缓存（24h TTL）+ 只分析选中资产（D06）+ 6MB 上限，天然压低调用量 |

### 3.6 localStorage 数据保护（MEA-04）

| 项 | 现状 / 做法 |
|---|---|
| 现状 | `visual-memory:v1` 单 JSON 全量重写；41 条 ~60KB，5MB 配额 ≈ 127 条 |
| 上限 | 新增容量常量 + 超限软降级（提示导出 / 拒绝新上传，不静默丢数据）|
| 损坏恢复 | 解析失败 → 备份原串 → 重建空库 → 提示（MEA-04 已立项）|
| 可选 | IndexedDB 迁移（容量 Gate 触发时立项，非当前）|

### 3.7 HTTPS / CORS

| 项 | 做法 |
|---|---|
| HTTPS | 平台托管自动提供（Vercel/Netlify/CF Pages 均免费证书）|
| CORS | **保持无 CORS 头 = 强制同源**（现有架构既如此）。公网形态下前端与 bridge 同域，浏览器天然同源；跨域调用将被浏览器拦截 —— 这是特性不是缺陷 |

### 3.8 错误监控与回滚

| 项 | 做法 |
|---|---|
| 日志 | serverless 平台日志（脱敏摘要形态，P6.3.2 已定型：`[vision-validate]` 只含 code/counts）|
| 错误码 | 现有机器可读错误族（400/413/502/503 + intent-* 码）直接可观测 |
| 告警 | 平台 error-rate 告警 + 费用告警 |
| 回滚 | 静态托管回滚到上一 dist 版本；serverless 回滚到上一函数版本；密钥版本化支持回退 |

### 3.9 预估月度成本

| 项 | 量级（个人作品集）|
|---|---|
| 前端托管 | $0（Vercel/Netlify/CF 免费档）|
| Serverless 函数 | 免费档足够（月度调用远低于平台免费额度）|
| Vision Provider | **唯一主要成本**。按调用次数计费：作品集演示级（~100 次/月）远低于付费门槛；重度使用需按 provider 单价估算 |
| 合计 | 接近 **$0–少量**；成本弹性完全由 Vision Provider 调用次数决定 |

> ⚠ **部署硬前置（VALIDATION_GATES.md）**：Balanced 60 通过 + 六项验收（鉴权/限流/日志脱敏/存储保护/留存核查/公网 E2E）全部通过，才允许公网部署。本文档是**架构方案**，不是部署执行。
