# 核心技术决策与理由

> 每条都写「当时的处境 → 为什么不选另一条 → 后来怎么验证」。
> 只写结论的设计文档没有信息量。

---

## 1. 首页复用 FIND 管线，而不是另写一套

**处境**：UI 简化要求首页有搜索；FIND 已经有完整、已验收的检索管线。

**选择**：`renderFind(app, { asHome: true })`，首页**就是** FIND 的一个模式。

**否决的方案**：给首页写一套「精选 + 简易搜索」。理由是会产生第二个行为分叉点 ——
修好首页忘了 FIND、或者两边结果不一致，缺陷排查成本翻倍。项目里已经因为「两份相似逻辑」
付过代价：截图脚本一度只数 `<img>`，把耗尽回退的卡片当隐形，导致指标好看但用户看到的是占位块。

**验证**：首页搜索与 FIND 走同一条 `parseVisualIntent → retrieveByIntent`，
E2E 里「快速连续查询后结果属最后提交的查询」等竞态断言对首页同样成立。

## 2. 图片超时只在进入视口后启动

**处境**：冷启动时图片墙 20 张里有 16 张显示「图像暂不可用」。

**根因**：浏览器对 `loading="lazy"` 的图片，在被滚动进视口前**不会发起请求**。
而超时器是「设了 `src` 之后 N 秒没 `complete` 就判失败」—— 于是把**从未开始加载**的图片
判成了加载失败。

**选择**：`IntersectionObserver`，进入视口才 `arm` 计时器。

**否决的方案**：调大超时时间。那只是把误判窗口推后，且对真正的慢图更不利。

**验证**：冷启动 20/20 可用、占位 0（修复前 4/20、占位 16）。验收脚本按**视口内**统计解码，
不把视口外的图算成失败。

## 3. 参考登记只接受字符串 key

**处境**：侧栏「使用参考」点了有提示，CREATE 却收不到任何参考。

**根因**：`recordReference(key)` 第一行 `if (!key || typeof key !== "string") return getSnapshot();`
我传的是 `{ title, creator, key }` 对象，函数**静默返回、不报错**。

**为什么上一轮没发现**：那一轮的验收只断言「提示语出现」，没断言「CREATE 里真的有这张卡」。
**空 DOM / 未验证的副作用 = 假 PASS。**

**选择**：`recordReference(artwork.key)`，并在调用点写明为什么必须是字符串。

**验证**：CREATE 里断言参考存在 + `is-on` + `aria-pressed` + 去重，三者缺一不可。

## 4. TaskContext 参考不受 12 件上限截断

**处境**：用户刚选的作品不在 CREATE 参考区里。

**两层原因**：登记没生效（见上），**并且** `picks.slice(0, 12)` 会把排在后面的作品挤出可视区。

**选择**：参考区先放 TaskContext 参考（不受上限约束），默认候选按 id 去重后补位。

**顺带的诚实性约束**：去掉 `hasAnalysis` 过滤后，无分析记录的作品照常显示真实作品与来源，
但明确标注「无分析记录 · 只贡献来源信息」，**不生成任何分析字段**。缺字段由 `read()` 自然缺席，
不是补默认值。无图作品显示「无图」文字卡，不塞占位图。

## 5. 皮肤只保留两套，A 为默认

**处境**：两个视觉方案竞争，都做得不错。

**选择**：A「画册」为产品默认（`<html data-skin="album">`），B 留在同一个样式表里作设计存档，
截图脚本只拍 A。

**理由**：同时在售两套主题，等于每个新人都要重新回答「哪个是真的」。
存档的成本是一行 CSS，收益是保留设计探索的证据。

**不开发第三套** —— 这是明确的产品决定，不是技术限制。

## 6. Vision 通道 fail-closed

**处境**：服务端持有付费 Key，任何疏漏都会变成账单。

**选择**：
- 凭据只存在于服务端进程环境变量；构建产物不含任何 `VISION_*` 值
- Provider 已配置但**未配预算账本 → 拒绝调用**
- 未配置时 UI 显示 `not-configured`，**不用本地检索结果冒充识图**
- 静态服务默认根是 `dist/`，服务源码树必须显式传参（项目目录里有 `.env`）

**否决的方案**：「没配预算就先用着」和「默认开放本地模式」。前者把疏漏变成账单，
后者让「默认不安全」变成常态。

## 7. Skill 直接 import 产品代码

**处境**：Skill 需要检索与分析能力。

**选择**：`import` `src/services/**` 里的同一份实现，不复制。

**理由**：复制一份检索逻辑，就等于给 Skill 和网页制造行为分叉 ——
以后所有评分调整都要改两处，漏一处就是「命令行和网页结果不一样」。
硬性要求里也明确禁止「在 Skill 中再写一套独立的电影搜索算法」。

**实测校验**：Skill 跑出来的 Prompt 结构与网页点「导出 Markdown」完全一致，
因为它们调的是同一个 `buildPromptExport` + `promptExportToMarkdown`。

## 8. 验收必须从干净克隆跑

**处境**：开发副本里文件都在、模块都有缓存、`qa/ui/` 有 1.8 GB 历史证据。

**两次教训**：
1. `qa/ui/` 整个目录没进候选仓库，但 README 已经写了「这些 harness 可运行」。
   **本地永远有文件，只有换目录才会发现它不在版本控制里。**
2. 390px 前置检查只探了一次，冷目录下模块还没执行完 → 把通过判成失败。

**固定做法**：验收前 `git clone` 到新目录，不带 `node_modules`、不启已在跑的服务。

**另一条**：断言前必须先验证组件存在（`verify` + `waitFor` 轮询），
否则空 DOM 会让 `0 === 0` 变成 PASS。确认本身也要轮询，否则冷启动会把 PASS 变成 FAIL。

**第三条**：验收脚本**串行**跑。并发时两个 Edge 实例共用 profile 目录，
后启动的探针返回 `undefined`，产生假失败 —— 我为此误判过一次 19/23。

## 9. 外部来源不可用时降级，但不隐瞒

**处境**：Met 的 `/public/collection/v1/search` 已于 2026-10-01 退役（HTTP 410）；
AIC 与 Rijks 的可达性随时间波动。

**选择**：适配器失败时给出明确降级说明（E2E 8a/8b 就在测这个），不静默返回空列表假装「没找到」。
Skill 里进一步区分「请求成功」与「有命中」：0 命中报 `ok:false, empty:true` 并说明
命中了哪些概念词、哪些词未映射。

**理由**：一个影视工具如果对素材来源含糊其辞，它的核心价值（可核验）就没了。

## 10. 一处需求无法按原样满足时，如实记录

要求「增加一件没有分析记录的陌生作品验证」。实测本地 51 件档案中 46 件有图，
**全部都有分析记录**，不存在这样的作品。

**选择**：不伪造一件，改用「无图作品」作等价案例验证显示路径，并在验收报告里写明
「此项按原样不适用」。

**理由**：造一件假数据来满足验收条目，等于让验收报告失去意义 ——
而这类报告的全部价值就在于它可信。
