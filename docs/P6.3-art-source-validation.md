## 1. 实测发现的两个真实 API 变化（本阶段最有价值的产出）

### 1.1 Met Museum 搜索端点已于 2026-10-01 退役

```
GET /public/collection/v1/search
→ {"message": "... was retired on 2026-10-01. It was backed by Solr ...
             use /public/collection/v1.1/search, which is Elastic-backed
             and paginated via offset and limit."}
```

| 端点 | 状态 |
|---|---|
| `/public/collection/v1.1/search` | ✅ 200 `{"total":34601,"objectIDs":[...]}` |
| `/public/collection/v1/objects/{id}` | ✅ 200（**未随搜索迁移**） |
| `images.metmuseum.org/.../web-large/*.jpg` | ✅ 200 `image/jpeg` |

**影响**：项目内既有 `src/services/adapters/metAdapter.js` 若仍用 v1 搜索，**在今天的线上环境已失效**——而且它不检查响应体的 `message` 字段，会把这段错误文本当成「0 结果」静默处理。

本阶段**未修改该文件**（超出「只新增 source adapter」的范围），但记录在此。P6.4 前应修。

### 1.2 Rijksmuseum 的真实IIIF URL 在顶层 `isShownBy`，拼接路径 404

```
探测：https://iiif.micr.io/SK-A-1935/full/843,/0/default.jpg  → 404
实际：https://iiif.micr.io/hodeb/full/max/0/default.jpg          → 200
```

既有 `rijksAdapter.js` 的注释声称走「`iiif.micr.io/<imageId>/full/{w},/0/default.jpg`」，且 `toRaw()` 从 `aggregatedCHO` 里取 `isShownBy` —— 但该字段实际在 **edm-framed 文档的顶层**。两个问题叠加导致该适配器当前取不到图。

**另测**：`edm-full` 与 `ldjson` profile 均返回 **406 Not Acceptable**，只有 `edm-framed` 可用。

本阶段新适配器用实测的真实 URL，仅改写尺寸段：`shownBy.replace("/full/max/", "/full/960,/")`。

实测成功样例：

```
200106038 | Landschap met stenen brug                       | Rembrandt van Rijn | c. 1638
200107928 | The Night Watch Militia Company of District II…  | Rembrandt van Rijn | 1642
```

## 2. 唯一新增模块

```
src/services/source/artSourceAdapter.js
```

| 导出 | 作用 |
|---|---|
| `metSource` | v1.1 搜索 + `/objects/{id}` 解析 |
| `aicSource` | Elastic 分页搜索 + IIIF URL 构造 |
| `rijksSource` | `iterateIds()` 异步分页 + `fetchObject()` edm-framed 解析 |
| `materializeRecord()` | 下载真实字节 + 魔数校验 + sha256 + 落盘 |

**边界确认**：该模块**不从冻结层 import 任何东西**，也**不被冻结层 import**。它只产出「文件 + 溯源」的原始资产记录；把记录变成 VisualMemory 需要 intent，那由 `build-p63-archives.mjs` 在冻结层之外编排。

## 4. 真实性门禁（metadata 不完整即拒绝入库）

`metadataComplete()` 要求 6 个字段全部非空。Small 档拒绝 5 条：

| 来源 | 作品 | 拒绝原因 |
|---|---|---|
| met | *Landscape* (Ralph Albert Blakelock) | `incomplete-metadata(year)` — Met 返回 `objectDate` 为空 |
| met | *Case (Inrō)… Wood Rafts* | `incomplete-metadata(creator)` — `artistDisplayName` 为空 |
| met | *Case (Inrō)… Full Moon* | 同上 |
| met | *Portrait* | 同上 |
| met | *Landscape* (Perugino) | 同上 |

**这是门禁在工作，不是失败**。这些条目在真实用户产品里应当被跳过，而不是带着空 creator 进入个人画像。

## 6. 规模与成本实测

| 指标 | 值 |
|---|---|
| 单张平均体积 | **170 KB**（preview 档，web-large / IIIF 843px / Rijks 960px） |
| 1000 张预估 | **约 169 MB** |
| 下载节奏 | 串行 + 指数退避；Rijks 每条需2 次请求（search + resolve） |
| 断点续跑 | 支持（已存在且 >8KB 的文件跳过重下，重算 sha256 复用） |
| 跨源去重 | 按 sha256（两馆可能藏同一画） |

### 为什么选 preview 档而不是original

Met 的 `primaryImage` 原图常在 10–100 MB。视觉语言识别与检索都不需要原图，`web-large` 足以。若未来要做高分辨率局部检索，`materializeRecord()` 只需改 `tiers.detail`。
