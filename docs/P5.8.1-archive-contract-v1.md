# P5.8.1 STEP 1 — Personal Archive Contract V1

> 唯一备份格式。不多套格式、不引入 ZIP（审计判定：~40KB/条 × 数百条 = 单文件数 MB，JSON 足够）。
> 本契约即 P5.8.1 冻结物：完成后 P5.8.2 不再修改，除非 blocker / regression / security issue。

## 外层结构

```json
{
  "format": "visual-archive",
  "version": 1,
  "exportedAt": "2026-10-03T00:00:00.000Z",
  "memoryCount": 34,
  "memories": [ /* VisualMemory 原样条目 */ ]
}
```

## 字段规则

| 字段 | 规则 |
|------|------|
| `format` | 恒 `"visual-archive"`；import 时必须精确匹配，否则拒绝 |
| `version` | 恒 `1`；import 只接受 `1`（未来版本走显式迁移，本契约不做自动升级） |
| `exportedAt` | 导出时刻 ISO-8601 |
| `memoryCount` | 必须 === `memories.length`，不符即拒绝（防手改损坏） |
| `memories[]` | VisualMemory 原样（id/source/status/error/image/metadata/visualIntent/userData），**不做任何转换**——恢复即原样 upsert |

## 图片恢复信息

- `userData.thumbnail`（420px JPEG data URL 或远程 URL）随条目原样携带——这是当前产品唯一持久化的图像资产（审计 §C）
- **明示边界**：Archive 不含原图字节（产品从未持久化原图）；恢复后视觉记忆完整可用（检索/画像/Assistant 全部基于结构化数据），图像显示为缩略图
- 远程 URL 型 thumbnail 原样保留；import 不校验 URL 可达性（离线容忍）

## 数据边界（契约级承诺）

Archive **只包含** Personal Memory（`visual-memory:v1` / `MEMORY_STORE_DIR/memories.json` 的内容）。

**绝不包含**：artwork cache（artworks.json）、artService 搜索缓存、#eye 浏览行为画像（utils/profile.js）、QA fixtures、应用资源。

## Import / Restore 语义

- **校验**：format/version/memoryCount 三重校验，任一不符 → 整体拒绝（`{ok:false, reason}`），不做部分导入
- **mode "merge"**（默认）：逐条按 id upsert（同 id 以 archive 版本覆盖——恢复语义）；返回 `{ok, restored, skipped[]}`
- **mode "replace"**：先 `clearPersonalMemory()` 再逐条导入——clear 只删 Personal Memory（审计 §F 边界）
- 条目级校验：id 非空 + visualIntent 为对象 + status 合法；坏条目跳过并记入 skipped（不中断）

## Clear 语义

`clearPersonalMemory()` 仅清 Personal Memory 存储（browser: `removeItem(BROWSER_KEY)` + 缓存重置；node: 重写空 store）。Artwork cache / #eye 画像 / QA fixtures 不受影响——由 QA 断言固定。
