# P5.6.0 — Assistant Readiness Audit

> 只读审计，零代码修改。目标：确认现有 V2 Alpha 能力是否足以支撑 Personal Visual Assistant 薄层。
> 边界：不做大 Agent / 不做自治工作流 / 不引入复杂后端 / 不修改 V2 Alpha 核心冻结层。

## 已有能力盘点（逐组件核验）

| 组件 | 状态 | 与 Assistant 的关系 |
|------|------|---------------------|
| VisualMemory（memoryRepository） | ✅ | 个人资产池（local-first，34 条真实池）；`listMemories()` 可组合读取 |
| 图片理解（Vision → VisualIntent 25 字段） | ✅ | 冻结层，Assistant 零触碰——资产已带结构化视觉语言 |
| 视觉检索（retrieveVisualMemory） | ✅ | 冻结 scoreIntent 唯一评分器；返回 `{id, score, possible, matchedFields, reasons, memory}`——Assistant 的 find_reference 直接组合 |
| 个人画像（visualProfile） | ✅ | 冻结聚合器：`buildVisualProfile()` / `getConfidence()` / `aggregateVisualProfile()`——Assistant 的 understand_taste 直接组合 |
| Presenter（visualProfilePresenter） | ✅ | 冻结展示层：`profileSections` / `confidenceHeadline` / `unavailableBlock`——taste 文案可复用，语气纪律（0.55/0.4 分档）已被冻结固定 |
| UI Flow（#memory 四路由 + profile + 三 CTA） | ✅ | `#memory/assistant` 可作为新增路由挂入（见下方边界说明） |

**结论：四个基座能力全部在位**——图片理解 ✅ / 个人资产 ✅ / 视觉检索 ✅ / 个人画像 ✅。Assistant 层是纯组合层（thin composition），不需要重新实现任何能力。

## 缺失能力（本阶段要补的三件事）

1. **自然语言入口**——目前检索是结构化选择（刻意的 V1 决策），画像页是固定展示。用户说「找孤独荒原感觉的参考」时没有入口。补法：**规则式 NL→VisualQuery 映射**（关键词→schema 字段/token），零 LLM 调用、零意图识别模型；未映射词诚实收集并明示，不假装理解。
2. **任务编排层**——目前三个能力（画像/检索/资产）彼此独立，没有「根据任务组合调用」的层。补法：`visualAssistant.js` 薄层，输入 `{task, query, context}`，按 task 分派到 profile / retrieval / 二者组合。**编排 = 一次 if/switch + 组合调用，不是 Agent Loop。**
3. **回答格式**——目前各层输出数据结构，没有面向「创作者提问」的回答封装。补法：三个 task 各自的回答 schema（taste: summary+evidence+sampleSize+confidence / find: query+results[{image,reason,matchedFields}] / creative: brief{directions+references}+basedOn），全部强制携带证据与样本量。

## Agent 边界（本阶段设计纪律，写入实现）

- ❌ 不做：AutoGPT / Agent Loop / 自主规划 / 联网搜索 / 自动生成导演方案 / 替用户决策 / 聊天窗口
- ✅ 只做三能力：Understand My Taste / Find My References / Assist My Creation
- Assistant 的「理解」= 规则映射 + 冻结画像；「寻找」= 冻结检索；「辅助」= 个人记忆的结构化整理。**没有任何一步是生成式创作或决策**——创意方向全部来自用户已收藏资产的语言统计，每条输出可追溯。

## 冻结边界说明

`visualAssistant.js` / `#memory/assistant` 页面为**新增文件**（冻结面外）。router.js 新增一个分支、memory.js 新增一个 CTA 属于对 V2 UI 冻结文件的**加法修改**——按冻结三问记录：① 为什么需要：用户显式开启 P5.6 Assistant 层，需要入口；② 是否破坏边界：否——加法路由/CTA，不改动任何既有行为与数据规则；③ 是否新版本：P5.6 为用户显式授权的新阶段。Profile/Vision/Retrieval/Schema 四个核心冻结文件零触碰。

## 判定

**GO** —— 四基座在位、三缺失均为薄层可补、无一处需要动冻结核心。进入 STEP 1。
