## 1. 产品原型是什么

一个最小距离感的产品：**把你的视觉素材变成一张张「视觉卡片」**。

用户打开产品 → 从主导航进入 MEMORY → 上传任意一张图（电影剧照 / 绘画参考 / 照片 / AI 生成）→
服务端识图模型把这张图读成一组视觉语言（情绪、氛围、光线、构图…）→ 保存进个人档案 →
档案页出现一张带中文视觉标签的卡片 → 点进详情看完整解读 → 刷新后收藏仍在。

只做这一件事。没有检索、没有推荐、没有用户系统、没有云同步。

## 2. 用户流程（MVP User Flow）

```
打开产品 (#index)
  → 主导航 MEMORY (#memory)           档案索引：空状态 → 引导去上传
  → 上传 (#memory/upload)             选图/拖图 → 预览 → 填名称/来源/标签/备注 → 分析并保存
  → 服务端识图 (/api/vision)          真实模型 → normalizeVisionIntent → VisualMemory
  → 保存 (localStorage visual-memory:v1)
  → 跳转详情 (#memory/:id)            中文视觉语言解读 + 你的备注 + 标签
  → 返回档案 (#memory)                卡片列表（缩略图 + 中文视觉标签）
  → 刷新/重开页面                      收藏仍可见（localStorage 持久化）
```

## 3. 页面设计（仅 3 个页面）

| 页面 | 路由 | 内容 |
|---|---|---|
| 档案索引 | `#memory` | 「你的视觉档案」+ 上传入口 + 卡片网格（缩略图、来源、日期、4 个中文视觉标签、删除） |

产品纪律落实：**不显示「推荐类似」**——本阶段没有检索/推荐，页面上没有任何推荐区块。

## 8. What Works

- 上传 → AI 视觉分析 → 视觉卡片 → 保存 → 刷新可见 的完整闭环真实可用
- 视觉意图字段全部以中文呈现（氛围·情绪、色温、饱和度、留白、光线、机位、构图…），一眼可读
- 失败诚实：provider 未配置/网络错误时明确提示「保存失败（code）：message」，绝不伪造 intent、绝不落库
- 删除可用，档案为空时有引导文案
- localStorage 持久化，数据不出浏览器（产品原型无后端依赖）

## 9. What Does Not Exist Yet（诚实边界）

- **浏览器 UI 自动化验证**：agent-browser 在本环境无法启动 Chromium，DOM 层交互（拖拽、点击、跳转）未经真实浏览器点击验证；
  已通过构建产物核验（路由/导航/页面/样式就位）+ 真实数据链路 + localStorage 语义测试覆盖
- **电影剧照真实素材**：项目内无电影剧照图片（P4.4 已记录 MISSING_IMAGE），TC1 使用公有领域绘画 + film-still 来源标签验证链路
- **个人视觉检索**（P5.2）：档案目前只能浏览/删除，不能「按视觉特征找回」——这是本阶段刻意不做
- **多设备/云同步**（P5.3+）：数据只在 localStorage
- **用户系统 / 登录 / 分享**：本阶段禁止
- 上传元数据（名称/来源/标签/备注）只作编辑性展示，**永不参与任何检索或评分**（延续 P4 纪律）

## 10. Next Decision（下一步决策）

产品原型证明了「用户会保存视觉素材」的最小闭环真实成立。下一步两条路，需要用户选择：

**A. P5.2 Personal Retrieval（推荐，延续路线图）**——在档案之上加一层「按视觉特征找回」：
复用冻结 `scoreIntent` / `sharedReasons`，个人池 top-N，把「收藏」变成「可检索的个人视觉资产库」。
架构已冻结无需重构，只加 repository 抽象 + 一个检索薄层。

**B. 先做浏览器内真实体验验证**——在具备 Chromium 的环境重跑 3 个 Test Cases 的 DOM 层（真实点击/拖拽/刷新），
确认 UI 交互无问题，再进 P5.2。

建议：先 B 后 A——产品体验必须先被真实点击验证过，检索层才有意义。
