## 8. Decision

### 产品问题（验收三问）

- **为什么用户保存？** 保存理由=「把可复述的视觉感觉留下来」（电影剧照/画作/参考的"感觉"能被 AI 转译成语言）——保存动机真实存在；但 50% 失败率会杀死动机。
- **保存后获得什么？** 当前只获得「一张可读的视觉卡片」（10/10 命中 + 5/10 新洞察，价值成立）；**没有获得"再次利用"**（找不回 = 二次使用全失败）。
- **为什么回来？** 目前**没有理由回来**——没有检索、没有聚合、没有创作出口。这是 P5.1.7 最重要的产品结论。

### 技术问题

- **当前能力是否足够？** 核心转译能力足够（10/10 命中，P3.2 已校准 45/49）；**可靠性不足**（本次 50% 失败率 vs P3.2 的 92%）——provider 波动是当次最大瓶颈。
- **最大限制在哪里？** ① 上传链路无重试/批量（体验层）；② emotion 捕捉弱 + 寂静偏置（理解层，**schema 冻结**）；③ 无个人检索（价值层，P5.2 未做）；④ 素材输入仍受 6MB/单张限制。

### 产品路线问题（下一步只解决一个明确问题）

**两个强信号同时成立，但存在先后依赖：**

> 如果目标的下一步是"让产品先被用起来"，应优先解决 **上传可靠性**（失败重试 + 批量导入，A 类问题）——在 50% 失败率下，任何后续价值功能（检索/画像）都建立在用户可能存不满的空库上。
>
> 如果目标的下一步是"验证核心价值假设（个人视觉资产可再次利用）"，则优先 **P5.2 Personal Retrieval**——二次使用测试 3/3 失败的"找回"缺口是唯一被验证的价值断层，且实现路径已冻结（零 Core 改动）。

两个方向都需要而不是二选一时，建议顺序：**A 类可靠性修复（小、前置）→ P5.2 Retrieval（价值层）**。若用户确认"库可以不满、先验证价值"，则可直接进 P5.2。
