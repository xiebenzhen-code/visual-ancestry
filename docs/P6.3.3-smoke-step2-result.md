### 7.6 归因结论（用户贴出 Bridge 终端 diag 后）

**失败层级 = Provider 内容层截断（L2）· `finish_reason=length`**，铁证如下（用户提供的 `[fa-vision-diag]`）：

```
model            : glm-5.3（上游实际模型）
outerJsonValid   : true（传输层 JSON 合法，HTTP 200）   ← 排除 transport-invalid
finishReason     : length（上游达到 max_tokens 被截断）
usage            : { promptTokens:1480, completionTokens:800 }  ← 800/800 用满
contentLength    : 321（content 在 321 字符处截断）
innerJsonValid   : false · SyntaxError
parseErrorMessage: "Expected double-quoted property name in JSON at position 321"
                  （字符串在属性名中途被硬切 → JSON 未闭合）
```

**根因机制**：冻结请求参数 `openaiProvider.mjs:292` `max_tokens: 800`（D13 冻结，零改动）。GLM-5.3 在 800 completion tokens 内**无法完成** 22 字段 JSON（含 emotion/atmosphere 数组），输出被 `finish_reason=length` 截断 → content 不完整 → 内容层 `JSON.parse(stripFence(content))`（`:202`）失败 → `invalid-json` → bridge 502 诚实失败。

**与 E02 / D13 登记风险完全吻合**：
- `ERROR_REGISTRY.md` E02（OPEN，Blocking=Yes）："reasoning 挤占输出预算，结果时好时坏"；
- D13 Trade-off 原文预告："reasoning 预算问题若导致 `max_tokens:800` 下 content 为空/被吃满，bridge 会返回 502（诚实失败），不伪造成功" —— **本次为首次实锤**；
- 注意区分：E01 是 `content_len=0` 空响应（REJECTED）；**本次是有 321 字符 content 但被截断**，属截断型而非空响应，故 E01「不要当单因修复」的警示不直接覆盖本场景。
