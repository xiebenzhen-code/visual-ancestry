## 1. Current Product Definition

### 一句话定义

```
这是一个 把任意图片转译成结构化视觉语言（光线/构图/色彩/氛围/情绪）并沉淀为可浏览的
个人视觉卡片库 的工具。

帮助 影视 / AIGC 创作者 与 设计师 这类需要"读懂画面语言、组织视觉参考"的用户。

通过 服务端识图模型 → 冻结 VisualIntent 归一化 → 本地持久化的个人视觉记忆存储 能力。

解决 图片的"感觉"无法言说、视觉参考素材散落且无法按视觉特征组织 的问题。
```

### 定位边界（当前真实状态）

```
输入：任意图片（≤6MB，JPG/PNG/WEBP/GIF）＋可选编辑性元数据（名称/来源/标签/备注）
处理：/api/vision（冻结桥）→ normalizeVisionIntent（冻结纯函数）→ 25 字段 VisualIntent
输出：视觉卡片（中文视觉标签）＋本地档案（localStorage / Local JSON）＋浏览/删除
不做：检索、推荐、云同步、用户系统、批量导入、导出（截至 P5.1.5）
```

**禁止使用的空泛描述**（本报告回避）：AI 平台 / 智能助手 / 超级 Agent / 万能搜索——当前产品是**单一路径的视觉转译 + 收藏工具**，不是平台，不是助手，更不是搜索。

## 2. Target User

### 用户 A — 影视创作者（导演 / 摄影 / 剪辑 / AIGC 创作者）

| 维度 | 分析 |
|------|------|
| 使用场景 | 创作前期收集参考帧与剧照；选景、打光、调色沟通；AIGC 提示词提炼（想复现某种画面感） |
| 痛点 | 参考图按文件夹堆放无法按"感觉"找回；"我要那种孤独感、冷色调、大空间的镜头"只能靠记忆翻找；团队沟通时视觉描述不一致 |
| 产品匹配度 | **中高**。VisualIntent 字段（机位/光线方向/色温/情绪/氛围/构图）与影视语言**同构**——他们描述镜头的方式就是这套词汇。但当前产品只覆盖"沉淀"环节（存 + 看 + 删），未覆盖"复用"环节（按感觉找回、导出给团队）→ 匹配的是收藏动作，不是创作流程 |

### 用户 B — 设计师（视觉 / 平面 / UI）

| 维度 | 分析 |
|------|------|
| 使用场景 | 情绪板（moodboard）收集、配色/构图/质感参考、灵感库整理 |
| 痛点 | Pinterest/花瓣收藏是关键词标签（"城市""蓝色"），无法按视觉感受组织（"低饱和、大留白、疏离"）；收藏即吃灰 |
| 产品匹配度 | **中**。中文视觉标签（色温/饱和度/留白/密度/对比）几乎就是设计术语，比关键词更接近设计语言——这是真实加分点。但设计工作流需要批量导入（一次几十张）、分组、导出情绪板；当前原型一次一张、无分组无导出，**工作流级不匹配** |

### 用户 C — 普通图片收藏用户

| 维度 | 分析 |
|------|------|
| 使用动力 | 喜欢画面、想留住"感觉"、收藏即拥有 |
| 长期维护意愿 | **低**。收藏工具竞争激烈（相册/收藏夹/社交平台）；一次一张上传 + 识图等待是负担；"视觉语言卡片"对非专业用户是锦上添花而非必需品；无社交/分享回路 |
| 产品匹配度 | **低**。除非"按感觉找回"神奇到改变习惯——但普通用户很少回头检索自己的收藏 |

### 匹配度结论（不做商业成功判断，只判匹配程度）

**A（影视创作者）> B（设计师）> C（普通收藏用户）**。
当前产品最像"创作者的个人视觉资产库"，不像"图片收藏工具"。两个支撑证据：① 视觉语言字段与影视/设计语言同构（这是区别于一切关键词收藏工具的根）；② 真实链路上传测试全部通过，技术可行性无风险——风险在"创作者是否会在创作周期中回来用"，不在"能不能做出来"。

## 4. Missing Value（当前未解决）

| 未解决问题 | 影响 |
|------------|------|
| **为什么长期收藏？**（收藏出口不明） | 收藏后没有"再次利用"的动作，收藏本身无回报 → 使用频率停留在"一次性" |
| **如何再次利用？**（无检索/无导出/无联动） | 没有 P5.2 检索、没有情绪板导出、没有与 CREATE/SHOOT 创作页联动 → 资产不可调用 |
| **如何辅助创作？**（输出侧缺失） | 输入侧成立（图片→语言），输出侧缺失（语言→找图→进创作流程） |
| **批量与效率** | 一次一张 + 6MB 上限 + 识图等待，无批量导入/队列 → 高量用户（设计师）被工作流挡在门外 |
| **数据可携带** | localStorage 单机、无导出 → 积累越多越担心丢失，长期信任不足 |
| **增量价值感知** | 用户看不到"我的视觉库在变聪明"，只有条目变多 → 复利不可见 |

## 5. User Flow Review

```
上传图片 → Vision 分析 → VisualIntent → VisualMemory → 浏览
```

### 已解决

- 图片无法理解 → 结构化 VisualIntent（真实链路验证）
- 素材无法整理 → 统一 schema + 本地档案
- 视觉语言无法描述 → 中文视觉标签可读、可复述

### 未解决

- **为什么长期收藏** → 收藏的出口不明：收藏即终点，不是起点
- **如何再次利用** → 无检索（P5.2）、无导出、无创作联动
- **如何辅助创作** → 流程在"浏览"处戛然而止，没有回到创作（CREATE/SHOOT 未接入）

**流程判断**：当前是一条**单向沉淀链**（输入强、利用弱）。链条的每一环都真实可用，但最后一环（浏览）没有产出新价值——用户从"浏览"离开时，带走的是"我又多了几张卡片"，不是"我更会创作了"。

## 6. Product Experience Review（只看产品表达）

### 首页（#memory）— 用户感知：图片列表，不是视觉库

- 现状："已保存 N 段视觉记忆" + 卡片网格（缩略图/来源/日期/4 chips/删除）
- 问题：缺少"库"的聚合信息（我的视觉倾向统计、相似聚类、分组）。用户一眼看到的是"我存了几张图"，不是"我的眼光是什么"
- **表达缺口**：没有让用户获得"这是我的视觉库"的自我认知——而这正是"资产系统"与"收藏夹"的分水岭

### 上传（#memory/upload）— 分析价值有承诺、无过程

- 现状："AI 把它读成一组视觉语言" + 预览 + 表单 + "分析并保存" + 诚实失败提示
- 问题：分析过程不可见（等待期无转译反馈），价值只在跳转详情页后兑现。"分析并保存"对第一次用户是黑盒——他们以为只是"加个标签"
- **表达缺口**：没有让"转译"这件事的独特性（图片 → 一套创作语言）在动作发生前被感知

### 详情（#memory/:id）— 视觉标签，不是视觉语言叙述

- 现状：大图 + chips（氛围·情绪 + 20 项特征）+ 备注 + 标签 + 删除
- 问题：20 项 chips 是**标签墙**，不是**视觉语言叙述**。真正的视觉语言能连读成句（"冷色、低饱和、深空间、孤立人物 → 疏离的孤独"），当前是离散平铺，读不出画面感
- 亮点：字段本身选得对（就是影视/设计语言），缺的是组织方式——从枚举到叙述

### 表达评级

**架构到位、语言选对、组织方式未到位**。产品在"转译的准确性"上已经可信（真实 provider + 冻结 schema），但在"让用户理解自己拥有什么"上还差两步：聚合（首页）与叙述（详情）。

## 7. Next Phase Options（不评分，只说明适用条件）

### Option A — P5.2 Personal Retrieval（自己的视觉资产搜索）

**适用条件**：
- 目标是**把"收藏"变成"可检索的个人视觉资产库"，验证"100 张复利"假设**；
- 目标用户明确需要"按感觉找回"（影视创作者场景：输入"冷色 孤独人物 大空间"返回自己的收藏）；
- 接受 P5.0 已设计的实现路径：repository 抽象 + 冻结 `scoreIntent`/`sharedReasons` 组合，**零 Core 改动**。

**性质判断**：这是当前唯一能同时改变"使用频率"（收藏驱动 → 创作驱动）和"长期复利"（线性列表 → 可检索资产）两个维度的增量。

### Option B — 继续优化 P5.1.5 原型（卡片/展示/收藏流程）

**适用条件**：
- 目标是**先确认产品表达成立**（用户是否感知"视觉库"而非"图片列表"）；
- 上阶段遗留的**浏览器 DOM 体验验证**尚未完成（agent-browser 在本环境无法启动 Chromium，已诚实记录）；
- 想先验证"视觉语言叙述"（详情页从标签墙到叙述句）是否实质提升感知——优化应服务于验证假设，不是堆功能。

**性质判断**：小改动（首页聚合 + 详情叙述）即可测试表达假设；但按阶段纪律，优化不能替代"真实用户 + 真实剧照 + 真实使用频率"的证据。

### Option C — P5.3 External Reference Layer（博物馆/电影/用户素材扩展）

**适用条件**：
- 目标是**从个人库扩展到跨源对照**（博物馆/电影参考），或直接转向"跨源视觉图书馆"（那是另一个产品主线）；
- **前提是个人资产检索已成立**——在连"找回自己的收藏"都没有时扩展数据源，等于在空地上盖楼。

**性质判断**：当前阶段过早；P5.0 已给出 P5.3 的只读扩展设计（referenceService 不混 score），但触发时机应在 P5.2 之后。

## 8. Final Recommendation

基于当前验证结果：

- **如果目标是"确认产品是否值得继续投入、验证'个人视觉资产系统'假设"**，下一步更适合 **先完成一次真实浏览器 DOM 体验验证 + 最小表达修正**（首页补聚合感知、详情补叙述化），因为当前原型的关键风险不在技术（真实链路已通过），而在产品表达——用户是否理解这是"视觉库"而不是"图片列表"。
- **如果目标是"直接验证长期价值 / 复利假设（100 张后可利用）"**，则可以优先 **P5.2 Personal Retrieval**——它是当前唯一能改变"使用频率"与"复利"两个维度的增量，且 P5.0 已给出零 Core 改动的实现路径（repository 抽象 + 冻结 scoreIntent/sharedReasons）。
- **如果目标是"扩大覆盖面 / 做跨源视觉图书馆"**，再考虑 **P5.3**；但前提是个人资产检索已成立，否则外部参考没有可依附的资产层。

**产品判断总结（一句话）**：当前产品已可靠地证明"图片 → 视觉语言 → 可沉淀"成立，但它还不是"个人视觉资产系统"——差 P5.2 这一步，差"收藏之后能干什么"这一个答案。**产品成立性（是否有人长期使用）尚未被真实用户与真实素材验证，这是比任何功能缺口都更前置的风险。**
