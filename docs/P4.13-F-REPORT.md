## 2. STEP 1 — 入口一致性修复

### 2.1 修复前的实际分歧（实测）

| 入口 | 调用点 | `enhanced` | `querySig` 来源 | 排序函数 | American Gothic 的第一名 |

| 文字检索 | `find.js:438` | 有 | `null`（文本没有自己的像素） | 增强路径 | — |

两条路径给出**两个不同的第一名**。这不是阈值好坏，是逻辑自相矛盾。

### 2.2 处置：把「证据来源」显式命名

新增 `ENHANCEMENT_EVIDENCE` 与 `buildEnhancement()`（`src/services/retrieval/retrievalService.js`）：

| 证据 | 含义 | `querySig` | `querySignatureOrigin` |
|---|---|---|---|
| `uploaded-pixels` | 用户上传图**自己的像素** | 上传图签名 | `computed-from-uploaded-pixels` |
| `archive-signature` | 档案作品**已有的**像素签名（`color-signatures.json`，按 id 索引） | `signatureFor(artwork.id)` | `precomputed-local-asset` |
| `none` | 没有可比较的像素证据（文本查询 / 签名缺失） | `null` | `unavailable` |

三条设计约束：

1. **绝不把档案签名冒充上传像素。** `signatureFor()` 返回的 `origin` 保持 `precomputed-local-asset`，`assertUploadSignatureOrigin()` 会拒绝它。证据种类由独立的 `evidence` 字段承载，不靠 `origin` 混同。
2. **降级必须留痕。** 签名算不出来时 `querySig = null` **且**写入 `degradation` 说明，不把「没有色彩证据」伪装成「色彩很近」。
3. **证据不同就不强求结果相同。** 上传路径的证据是这张新图自己的像素，与档案签名本就不同，允许排序不同，但差异必须可归因到 `evidence`。

### 2.3 处置：消灭三个静默缺陷

#### BUG-1 缓存键串门

```
function intentOf(artwork, intentSource = "auto") {
  const cacheKey = `${artwork.key}|${intentSource}`;   // key 缺失 → "undefined|auto"
```

缺 `key` 时**所有作品共用同一个缓存槽**：先查的作品把 intent 写给后来者。实测 `{id:"starry"}` 与 `{id:"wanderer"}` 返回**完全相同**的 Top5。

处置：身份改为「`key`，否则 `id:` + id」，无身份可用时**不缓存**（无槽可归）。

#### BUG-2 未知作品静默回退

`retrieveByArtwork()` 对 `null`、空对象、未知 key/id 一律走 `intentOf → intentFromArtwork`，产出**看似正常但不相关**的榜单，且不报错。

处置：新增 `resolveRetrievalArtwork()` 与 `retrieveByArtworkChecked()`：

| 输入 | `error` | `results` |
|---|---|---|
| `null` / `undefined` / 字符串 / 数组 | `not-an-object` | `[]` |
| `{}` / 只有 `title` | `missing-key` | `[]` |
| 未知 `id` / 未知 `key` / 伪造前缀 | `unknown-artwork` | `[]` |

`retrieveByArtwork()` 保留数组契约（既有调用方不受影响），无效输入返回 `[]`。

#### BUG-3 id 兜底不可观测

`{id:"starry"}` 仍能解析到真实作品（这是合理兜底），但必须**可见**：新增 `resolution: "key" | "id"`，让「调用方没传 key、靠 id 兜住」这件事留在结果里，而不是静默。
