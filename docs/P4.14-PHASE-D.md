## 2. 一个必须写下来的实现发现：取景方式决定结果

模型自带的 `preprocessor_config.json` 是「最短边缩到 256 + 中心裁 256」。对绘画这是错的——**竖幅画会被切掉两侧，横向构图信息直接丢失**。

实测同一批 8 件作品，只换取景方式：

| 取景 | 与《美国哥特式》最像的前 2 名 |
|---|---|
| `crop`（模型默认） | `whistlers-mother` 0.748 → **`birth-of-venus` 0.721** |
| `pad`（等比缩放 + 居中补黑，保留整幅） | `whistlers-mother` 0.667 → `fan-kuan-travelers` 0.589 |

**用 `crop` 时，「维纳斯的诞生」排第二——和老算法犯的是同一个错。** 换成 `pad` 它掉出前五。

所以本实现固定用 `pad`，并在图库元信息里记下 `fit: "pad"`，测试里锁住这一条：

```js
assert.equal(vs.LIBRARY_META.fit, "pad", "取景方式必须是 pad —— crop 会让竖幅画被切边");
```

## 3. 结构关系特征（STEP 3A）

不改 22 键契约，另加一层。每个维度都带 `source`，拿不到就 `null`。

| 维度 | 来源 | 覆盖 |
|---|---|---|
| 画幅比例 / 方向 | **实测像素**（sharp 量 47 张真实宽高） | 47/47，比例范围 0.49–24.93（含长卷） |
| 人物数量级 / 尺度 / 关系 | VisualIntent 字段 | 有 intent 的条目 |
| 空间纵深 / 环境主导 / 留白 | VisualIntent 字段 | 同上 |
| 明暗 / 饱和度 / 冷暖 | 既有 `color-signatures.json` 主色加权 | 有签名的条目 |

**明确留空的维度**（写进 `unavailable` 数组，不补零）：

- `arrangement` —— 横排 / 并列 / 叠置：没有可靠字段
- `occlusion` —— 遮挡与层数：没有可靠字段
- `props` —— 前景道具：只有策展散文，未结构化
- `figureCount` —— 具体人数：VisualIntent 里只有 `subject: group` 这种桶

## 4. 三列对照（真实图片）

页面：`experiment/p414/index.html`，列名只有 A / B / C。

### 查询 =《美国哥特式》

| 列 | Top 3 |
|---|---|
| **A**（旧 VisualIntent） | 维纳斯的诞生 → 苏格拉底之死 → 吻 |
| **B**（纯图像向量） | **倒牛奶的女仆** → 林中拉达与克里希纳 → 惠斯勒的母亲 |
| **C**（向量 + 结构） | 倒牛奶的女仆 → 林中拉达与克里希纳 → 惠斯勒的母亲 |

**旧算法那个「不看画面只看标签」的问题，在 B/C 里确实被推翻了**：《维纳斯的诞生》不再第一。

### 查询 =《1808 年 5 月 3 日》

| 列 | Top 3 |
|---|---|
| **A** | 维纳斯的诞生 → 宫娥 → 大碗岛的星期天下午 |
| **B** | 维纳斯的诞生 → 圣马太蒙召 → 星月夜 |
| **C** | 维纳斯的诞生 → 维纳斯的诞生（另一尺寸条目）→ 星月夜 |

**这一组三列都以《维纳斯的诞生》开头。** 说明《维纳斯的诞生》在 CLIP 空间里是个「hub」——它是那种对很多查询都高度相似的图像。

### 所以能说什么、不能说什么

**能说：**

- 向量检索**确实**改变了排序，并且把《美国哥特式》的《维纳斯的诞生》挤了下去。
- 系统现在能展示**具体相似点与重要差异**（结构层逐维输出），不再只给一个分数。

**不能说：**

- ❌ 不能说《倒牛奶的女仆》就是比《维纳斯的诞生》更好的艺术参考。**这是审美判断，归你。**
- ❌ 不能说相关性已经「改善」。只有 1 个用户、1 张图的历史标注，且 P4.11 那 8 张里没有嵌入结果。
- ❌ 不能说《1808 年 5 月 3 日》那组变好了——它没变。

**这正好印证任务书那句：视觉嵌入不能直接当作艺术相关性的真值。**

## 6. 本地运行方法

```bash
# 1) 首次准备（模型 11 MB，自动下载到 .rc1-audit/p414/models/）
python -m pip install onnxruntime numpy

# 2) 生成图库向量（47 条，约 10 秒）
node scripts/p414/build-embeddings.mjs pad

# 3) 启动实验检索
node experiment/p414/server.mjs 4600
# 打开 http://127.0.0.1:4600/
```

重新生成向量的命令会自己量图片尺寸吗？不会——尺寸来自 `src/data/image-metrics.json`，由 sharp 一次性量好并入库。
