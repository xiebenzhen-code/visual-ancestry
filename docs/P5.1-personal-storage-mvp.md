# P5.1 — Personal Visual Storage MVP

Date: 2026-09-30 · **Status: P5.1 PERSONAL STORAGE MVP READY** · Core V1 fully frozen · Project positioning: AI art retrieval tool → **Personal Visual Asset Management System**

## 1. Architecture

```
User image
    ↓
Vision Bridge (/api/vision — frozen, same-origin, 6MB cap)
    ↓
normalizeVisionIntent (frozen pure function, strict enum whitelist)
    ↓
createVisualMemory (types.js contract — ONLY visualIntent participates in retrieval)
    ↓
memoryRepository.addMemory (local JSON, auto-init, idempotent)
    ↓
src/data/visual-memory/memories.json
```

This phase answers exactly one question: **can an image become a personal visual asset?** Yes — upload → bridge → intent → stored VisualMemory, with retrieval/search/sync/external/UI explicitly out of scope.

## 2. Data Contract

```jsonc
{
  "id": "vm-0001",                 // required, unique
  "source": "user-upload",          // required, ∈ MEMORY_SOURCES
  "image": { "path": "", "mime": "", "sha256": "" },   // required (sha256 may be empty for examples)
  "metadata": {                     // human/editorial — NEVER scored
    "title": "", "origin": "", "film": null, "year": null,
    "tags": [], "createdAt": ""
  },
  "visualIntent": { ... },          // required, normalized VisualIntent — THE ONLY retrieval field
  "userData": { "note": "", "collections": [] }   // user annotations — NEVER scored
}
```

- **Participates in retrieval:** `visualIntent` only.
- **Never participates:** `metadata`, `userData`, `image` (path/mime/sha256 are provenance only).
- Contract is enforced by `qa/memory/validate-memory-contract.mjs` (forbidden editorial keys inside intent → ERROR).
