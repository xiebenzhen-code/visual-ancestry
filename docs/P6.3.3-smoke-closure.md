## 4. 路径安全离线审计（证明问题，不直接采用未验证替代代码）

审计脚本 `work/p6.3.3/path-safety-audit.mjs` 以 server.mjs:23-27 当前实现为基准，19 个用例离线复算：

```
ESCAPED_ROOT 越界 = 0   （前缀 .. 被 strip 吞掉 + stat miss 兜底 → 实际未逃出 root）
THREW 异常      = 2    ❌ /%ZZ%nn、/%E0%A4%A → decodeURIComponent 抛 URIError → 500 + error.stack 泄露
内部文件可读    = 3    ⚠️ /../server/vision/openaiProvider.mjs、/../scripts/server.mjs、
                       /../docs/control/DECISION_LOG.md → 解析落在 ROOT 内且 stat 命中 → 会被静态服务直接读出
```

**结论（事实）**：
1. **未发生目录穿越逃逸**——当前 `strip /^(\\.\\.[/\\\\])+/` + `path.join(root,…)` 把 `..` 前缀剥掉、且目标文件多半不存在（stat miss → 回退 index.html），所以"逃出 root 读 /etc/passwd"在本用例集里不成立；
2. **但存在真实问题**：a) 畸形编码触发未捕获 URIError → 500 带 stack（`server.mjs:157-160` 泄露）；b) **`/../server/...` 这类"root 内但越权"的源码/文档可被静态服务读取**——因为 `..` 被剥成空后 `path.join(root,"/server/…")` 落在 root 内且文件存在 → `serveFile` 直接 200 返回源码（含 openaiProvider.mjs 结构、docs/control 决策记录）——这是**信息泄露**（虽不含密钥，但暴露内部结构与审计记录）；
3. 故路径安全**确有修复必要**，且不可沿用审查报告里未经验证的 safePath 替代（已按用户要求先构造用例证明，再给计划）。

### 变更 3 — 路径安全核验（P1，最小、已验证逻辑）
```js
function safePath(urlPath) {
  let decoded;
  try { decoded = decodeURIComponent(urlPath.split("?")[0]); }
  catch { decoded = "/"; }                      // 畸形编码→回退根
  const target = path.resolve(root, "." + decoded);
  if (target !== root && !target.startsWith(root + path.sep)) {
    return path.join(root, "index.html");       // 解析后越界→回退
  }
  return target;
}
```
（用 `path.resolve` 展开 `..` 后再做 `startsWith(root+sep)` 判界；`"."+decoded` 保证以 root 为基底、不以 `/` 或盘符重定根。）
