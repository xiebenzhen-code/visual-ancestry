# P5.8.1.1 — Personal Memory Lifecycle Contract

Date: 2026-10-03 · STEP 1 · 依据：`docs/P5.8.1.0-lifecycle-audit.md`（只读审计事实）

> 本契约定义 Personal Memory Lifecycle 的**行为规范、边界与不变量**：Bundle → Persist → Restart → **Export → Clear → Import → Restore → Continue Using**（粗体为本阶段新增/验证的环节）。实现、自动化 QA、真实生命周期测试、冻结均以此文档为唯一依据；P5.8.2 不再修改本契约，除非 blocker / regression / security。

---

## 1. 契约范围与数据格式

### 1.1 导出的标准格式（唯一可迁移单元）

```json
{
  "format": "visual-archive",
  "version": 1,
  "exportedAt": "2026-10-03T00:00:00.000Z",
  "source": "browser | node",
  "store": {
    "version": 1,
    "memories": [ ...VisualMemory... ]
  }
}
```

- `memories` = `listMemories()` 的**完整结果**（含 `status=failed` 条目——失败条目是「可恢复资产」，P5.1.8 哲学，导出不丢弃）。
- **诚实标注（UI 与文档）**：导出数据含每条资产的缩略图（≤420px JPEG dataURL）与全部视觉语言/元数据，**不含原始图片字节**（原始图从未进入 localStorage——P5.8.1.0 §2）。
- 导出 **永不** 调用 Vision / Retrieval / Scoring / Profile——纯序列化（读取当前 store 快照）。

### 1.2 导入的接受范围

- 只接受本契约格式：`format === "visual-archive" && version === 1` 且 `store` 结构合法。
- 裸 store（`{version, memories}`）与任何其他 JSON **拒绝**，报稳定错误码（不停留在猜测）。
- 逐条用 `createVisualMemory`（冻结构造函数）做 **schema 强制校验**；任何一条不合法 → **整体拒绝**，已有库不受影响（先全量校验、后单次写入）。

### 1.3 语义：导入 = 恢复 = 整体替换（非合并）

- 导入成功后**整库替换**当前库（replace 语义）。合并需要冲突策略（重复 id 处理等），超出本阶段范围，明确不做（记录为限制）。
- 导入成功前**自动先备份**当前库（内存备份，供失败回退与 UI「恢复后仍然不对」的撤回路径）。

## 2. 契约能力（模块 `src/services/memory/archivePortability.js`，冻结外新增）

| 能力 | 行为规范 | 错误码（稳定） |
|------|----------|----------------|
| `exportArchive()` | 返回 `{ ok, format, version, exportedAt, source, store, count }`；纯读快照 | — |
| `clearLibrary()` | 整体清空：调 `replaceAllMemories([])`（reposity 新原语，原子单次写）；返回 `{ ok, cleared }`；清后 retrieval 空、profile sampleSize=0、UI 诚实空态 | — |
| `importArchive(json)` | 全量校验 → 失败整体拒绝（库不变）→ 成功先备份再 `replaceAllMemories(validated)` → 返回 `{ ok, imported, rejected }` | `INVALID_JSON` / `INVALID_FORMAT` / `UNSUPPORTED_VERSION` / `INVALID_ENTRY`（含定位）/ `STORE_FAILED` |
| `verifyRestore()` | 一致性核验：`{ ok, storedCount, retrievableCount, hitCheck, profileSample }`——检索抽检（冻结 `retrieveVisualMemory`）+ 画像抽检（冻结 `buildVisualProfile`），**只调用不修改** | — |

## 3. Repository 最小修改授权（P5.8.1.0 §5 授权 B，已获审计证明）

`src/services/memory/memoryRepository.js`（V1 冻结）**仅新增一个原语**，既有 API（add/get/list/delete）逐字节不动：

```js
replaceAllMemories(memories)  // 整体替换 store（而非逐条 add 循环）
```

- 理由：原子性——逐条 delete+add 在 localStorage 配额 / Node 写盘中断时可能留下**半替换**状态；单次 `setItem`/`writeFile` 原子完成。
- 双环境一致：browser → `browserCache` 替换 + 单次写 localStorage；node → `nodeState.store.memories` 替换 + 单次持久化。
- 只触碰 store 字段；不触碰任何检索/评分/画像/上传逻辑。

## 4. UI 面（加法修改，冻结三问记录于 STEP 5 文档）

- 新路由 `#memory/manage`（数据管理页）：三操作——**导出**（Blob 下载 JSON）/ **导入**（file picker → 校验 → 确认替换 → restore → 跳转 #memory）/ **清空**（确认弹窗 → clear → 重渲染）。
- `router.js` + `memory.js` 各一处加法（新分支 + 索引页 CTA），**不改既有行为与数据规则**（P5.6 先例）。
- 文案诚实：导出提示「含缩略图，不含原图字节」；导入提示「将整体替换当前库，导入前自动备份」。

## 5. 自动化 QA 契约（`qa/memory/lifecycle-test.mjs`，离线零 mock）

1. **Roundtrip**：建 3 条库（2 success + 1 failed）→ export → clear → 断言空（retrieval 空 / profile sampleSize=0）→ import → count 恢复 3 → `store` 与导出 **JSON 深度相等**（逐位 lossless）
2. **校验拒绝**：损坏 JSON / 裸 store / 错误 version / success 缺 visualIntent / 非法 source / 重复 id → 全部整体拒绝，库保持导入前状态；rejected 含可读原因
3. **Restore 一致性**：恢复后 `retrieveVisualMemory`（已知语言命中）命中数 ≥ 导出前；`aggregateVisualProfile` sampleSize 恢复
4. **浏览器分支**：伪造 `window.localStorage`——export → clear（browserCache 重置生效）→ import → `?reload=` 新模块实例仍可见（刷新后持久）
5. **Clear 不碰冻结**：examples.json 不受影响；Vision/Scoring/Profile/Assistant 模块零修改（hash 校验）

## 6. 真实产品生命周期测试契约（STEP 4）

- 真实 provider 上传 ≥3 条 → Restart（新进程）→ Export 落盘 → Clear → 空态断言 → Import（从文件）→ Restore → **Continue Using**：`#memory` 索引可见 / 检索命中 / 画像 sampleSize 恢复 / Assistant find_reference 可用
- 导出物可迁移：跨目录（work/p5.8.1-lifecycle/）读取导入，模拟「换机器」

## 7. 不变量（任何实现/测试不得破坏）

1. Export→Clear→Import roundtrip 逐位 lossless（failed 条目、thumbnail、metadata 全保留）
2. Clear 后诚实空态（retrieval 空、profile empty、UI 空态文案）
3. 冻结模块（Vision/Retrieval/Scoring/Profile/Assistant）**零修改**——hash 逐位校验
4. `memoryRepository.js` 仅新增 `replaceAllMemories`，既有 API 不动
5. 导入全程零 Vision 调用；失败整体拒绝、库不变
6. Error 稳定码 + 用户可读中文原因并存；不伪造成功

## 8. 明确不做（本阶段边界，与 P5.8.1 §0.3 一致）

Cloud Sync / Account / Auth / DB / Object Storage / 多设备同步 / Embedding / Vector DB / Agent / 原图字节迁移 / 导入合并策略 / IndexedDB 迁移 / ZIP 打包。
