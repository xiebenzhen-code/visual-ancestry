# P5.7.0 — Creator Workflow Validation · Readiness Audit

> 只读审计，零代码修改。目标：确认 Assistant 现有能力是否足以承载「创作者工作流验证」——即验证它进入真实创作流程，而非停留于 Demo。
> 总原则：不新增产品能力、不改冻结架构；本阶段只允许薄层调用、测试数据、案例报告、Demo 流程。

## 输入能力核验（visualAssistant.js `mapQueryFromText` 规则表）

| 创作输入类型 | 支持情况 | 证据 |
|--------------|----------|------|
| 创作主题（如「荒原夜晚镜头」「短片视觉方向」） | ✅ 部分 + 诚实兜底 | 主题词映射到场景字段（荒原→留白+空旷、夜晚→氛围 token）；不可映射的主题词（工业废墟感/人物渺小/项目名）诚实进入 `unmapped` 并明示——不假装理解 |
| 氛围描述 | ✅ | ATMOSPHERE_RULES：空旷/寂静/夜晚/雾/热闹/阴郁（冻结 token 词表全覆盖） |
| 空间描述 | ✅ | 深空间/纵深/留白/空旷/巨大环境→spatialDepth/negativeSpace/environmentDominance |
| 色彩描述 | ✅ | 低饱和/高饱和/冷色/暖色/高对比→saturation/colorTemperature/contrast |
| 人物关系描述 | ✅ | 孤独/孤立/独自→isolated；人群/群像→crowd；疏离→socialDistance high |

已知边界（如实记录，不在本阶段修复）：「独行」「人物渺小」「粉色」「工业废墟感」等长尾表达不在规则表内——走 unmapped 诚实路径；creative_support 在场景语言不足以检索时自动以用户画像高频倾向补全（P5.6 机制）。

## 输出能力核验

| 要求 | 支持情况 | 来源 |
|------|----------|------|
| 历史参考 | ✅ | find_reference / creative_support → 冻结检索真实资产（title/image/medium/score） |

## 三 Case 预检（只读推演）

- **Case A 场景设计**（荒原夜晚/孤独/巨大空间）：场景语言可映射（negativeSpace+atmosphere+humanRelation+environmentDominance）；「人物渺小/工业废墟感」预期进 unmapped；negativeSpace 在池中覆盖率低（18%），预期走「个人倾向补全」路径——这正是要验证的真实工作流行为
- **Case B 角色视觉设计**（长期独行的人物）：「独行」预期 unmapped → sceneQuery 为空 → creative_support 画像回退 → 输出「你的收藏中存在…」式视觉关系（spec 期望形态）；farCamera 29% <40% 预期不被声张（诚实纪律）
- **Case C 视觉 Bible**：understand_taste 直接满足（sampleSize/confidence/evidence 齐备）；禁评价词由 QA 断言固定
- **STEP 3 跨项目**：film+painting 跨媒介已有实测（P5.6 场景 A：电影 2+绘画 4）；**Personal AIGC 如实预期缺席**——C 类资产不在 40 张池（P5.3.2 诚实限制：素材源不可得），本阶段如实记录不伪造

## 判定

**GO** —— 输入/输出能力满足三 Case 与跨项目验证；两处预期诚实降级（unmapped 长尾词、Personal AIGC 缺席）均为设计内行为，正是本阶段要记录的工作流真相。零代码修改进入 STEP 1。
