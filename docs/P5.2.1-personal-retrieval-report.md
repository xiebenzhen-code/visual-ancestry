# P5.2.1 Personal Retrieval MVP

Date: 2026-10-01 · **Status: P5.2.1 PERSONAL RETRIEVAL MVP PASS** · 薄检索层成立 · 零 Core 修改

> 验证命题：**用户能否通过视觉语言找回自己的参考资产**（不是"搜索准确率"）。
> 实现边界：新增 1 个个人层文件 + 2 个 QA 脚本 + 1 份报告；**未修改任何冻结组件**（retrievalService / artworks cache / scoring weights / VisualIntent schema / Vision bridge / provider adapter 全部未动）。

---

## Goal

把个人资产池从"只能浏览"推进到"可按视觉语言找回"：

```
创作需求 → 视觉语言查询（VisualQuery） → 个人资产匹配 → 解释为什么匹配
```

成功标准（非准确率）：
1. **个人资产可以重新被调用** ✓
2. **匹配依据来自视觉语言**（不是文件名/标签）✓
3. **用户看到结果后能回答"为什么推荐这些"** ✓（matchedFields + reasons）

---

## Architecture

```
VisualQuery（schema 真实 token 子集）
      ↓
Personal Memory Pool（memoryRepository.listMemories）
      ↓
准入过滤（isRetrievable：status=success && source≠empty/example）
      ↓
scoreIntent()（冻结，单一评分体系）
      ↓
排序（score 降序；score>0 且 reasons 非空）
      ↓
evidence { id, score, matchedFields, reasons, memory }
```

**与 Core 检索完全隔离**：不 import `retrievalService.js`/`artworks.js`/museum adapters；两个池（artworks vs personal memories）互不触碰。

### 关键实现决策

1. **评分零复制**：`scoreIntent()`（scoring.js 冻结）是唯一评分器——没有第二套 `if atmosphere +10` 逻辑。
2. **matchedFields 是最小派生**（审计确认代码中不存在）：纯相等枚举（标量相等 / 列表交集），**不读冻结 WEIGHTS**，不参与评分，只生成证据字段名。
3. **reasons = 冻结 sharedReasons + 列表字段标签补充**：冻结 `REASON_LABELS` 只覆盖 14 个标量字段（无 atmosphere/emotion）——而 atmosphere 会命中评分（0.8/项）。因此 evidence 层补充「氛围 · 寂静」「情绪 · 孤独」类标签（`personalReasons`，只影响证据文案，不碰评分）。
4. **准入规则（P5.1.8 契约消费）**：`status === "success"` 且 `visualIntent.source !== "empty"`（失败占位）且 `source !== "example"`（示例数据）。失败资产不是视觉资产。
5. **无 `index.js`**：现有代码直接 import 具体文件（如 `pages/memory.js` 直接 import memoryRepository），保持同样模式，不需要 index 聚合导出。
6. **VisualQuery 用 schema 真实 token**：`atmosphere/emotion` 为中文列表 token（`寂静/空旷/夜晚/雾/热闹/阴郁`），标量字段为英文枚举（`cool/deep/high/isolated…`）。第一版不做自然语言（不引入 `visualIntentParser.js`）。

## Evidence Examples

**Q3 第一名 —— ruv-c03《旅行中的范宽》**，查询「空旷自然环境」：

```json
{
  "id": "ruv-c03",
  "score": 10.3,
  "matchedFields": ["atmosphere", "subject", "environmentDominance", "spatialDepth", "negativeSpace"],
  "reasons": ["环境压过人物", "纵深很深", "留白很大", "氛围 · 空旷"]
}
```

用户看到的不只是"像"，而是**为什么像**——五条字段证据对应五处可检验的视觉事实。这正是 P5.2 成功标准 3。

## User Value

- **P5.1.7 Q3 的 3/3 二次使用失败已修复**：孤独城市镜头/荒原环境/低饱和夜景三类需求现在都能在个人池中按视觉语言找回。
- **证据驱动**：matchedFields 给出"匹配在哪"（字段级），reasons 给出"为什么像"（人话级）——不是黑盒相似度。
- **诚实性**：低匹配返回低分（Q2 的 1.8–2.5），绝不强行凑高分；无匹配返回空（QA Case 2 变体已验证）。
- **池隔离**：个人资产检索完全独立于 Core 博物馆检索，互不干扰。

---

## Limitations

1. **并列分数 → 区分度有限**：Q1/Q3 top-5 常同分（池内同质化——P5.1.7 已知 isolated 70%/deep 70%/low-sat 高频）。当前池"孤独大空间"画像下难以进一步排序；需更多样素材（真实用户收藏）或 P5.3 个人画像去差异化。
2. **查询是结构化 token，无自然语言**：第一版刻意不做 NLP；用户需懂 schema 词汇（atmosphere 中文 + 标量英文枚举）。这是范围决策而非缺陷。
3. **reasons 覆盖缺口**：冻结 `REASON_LABELS` 无 `subject`（1.5 分）等字段标签——若仅 subject 命中且无列表字段，score>0 但 reasons 空 → 被过滤（与 Core `retrieveByIntent` 同规则：score>0 且 reasons 非空）。个人层补充了列表字段标签，但标量缺口保留（不修改冻结）。
4. **验证池为隔离回测数据**：真实产品数据在浏览器 localStorage（本环境无法读取）；STEP 7 用的是 P5.1.8 回测隔离池（20 条真实 provider 结果，语义等价）。
5. **无 UI**：P5.2.1 是服务层验证，检索入口（查询表单/结果页）未建——属下一阶段产品化选择。
