## 2. 可复用组件（读码逐项确认）

| 组件 | 状态 | 位置 | 直接可 import？ | 备注 |
|------|------|------|-----------------|------|
| `normalizeVisionIntent` | **复用** | `src/services/vision/normalizeVisionIntent.js`（冻结） | ✓ | 输入任意对象→合法 VisualIntent 或 null；P5.2 查询预处理可复用（如需） |
| `scoreIntent` | **复用** | `src/services/retrieval/scoring.js`（冻结，Core V1 #7） | ✓ `import { scoreIntent }` | 签名 `(query, candidate) → {score, possible}`；**遍历 WEIGHTS，query 空字段自动跳过** → 天然支持部分查询；melancholy=low 否定规则也在内 |
| `sharedReasons` | **复用** | `src/services/retrieval/artworkIntent.js`（冻结） | ✓ `import { sharedReasons }` | 签名 `(queryIntent, candidateIntent, limit=4) → 中文原因标签[]`（如「留白很大」「纵深很深」）——用户可理解的"为什么像" |
| `matchedFields` | **⚠ 不存在** | — | ✗ | **代码中无此导出**。`sharedReasons` 内部有 `REASON_LABELS`（字段→中文标签）但**未导出**；返回的是标签文案而非字段名。P5.2 需新增最小纯函数派生（见 §4.3），**这不是复制评分**——只枚举"query 与 candidate 均非空且相等"的字段名，不读冻结 WEIGHTS |
| `VisualMemory` | **复用** | `src/services/memory/types.js`（个人层） | ✓ | 契约含 status/error；`visualIntent` 是唯一检索字段 |
| `memoryRepository` | **复用** | `src/services/memory/memoryRepository.js`（个人层） | ✓ | `listMemories()` 提供个人池；双环境统一 async API |
| `emptyVisualIntent` / `mergeIntent` | **复用** | `src/services/retrieval/visualIntent.js`（冻结） | ✓ | P5.1.8 已复用 `emptyVisualIntent()` 作失败占位；`mergeIntent` 可构造查询 intent（如需） |

### scoreIntent 行为边界（审计确认，P5.2 只组合不修改）

- **WEIGHTS 覆盖 19 个字段 + emotion(0.6/项) + atmosphere(0.8/项)**：subject/subjectScale/environmentDominance/spatialDepth/negativeSpace/lightDirection/lightQuality/saturation/contrast/cameraRelation/cameraDistance/cameraHeight/socialDistance/humanRelation/motion/visualDensity/colorTemperature/melancholy/arousal
- **不在 WEIGHTS 中的字段**（即使 query/candidate 相等也不影响 score）：`subjectPosition`、`composition`、`geometry`——冻结行为，P5.2 不改
- **部分查询天然成立**：query 只填有意图的字段，`if (!query[field]) continue` 自动跳过其余

### token 空间（审计确认，关键）

- VisualIntent 的 `atmosphere`/`emotion` 是**中文 token 空间**（`normalizeVisionIntent` LISTS：空旷/寂静/夜晚/雾/热闹/阴郁；情绪：平静/悲伤/孤独/喜悦/敬畏/不安/温暖）
- P5.1.8 回测 20 条 success 记忆的 atmosphere token 实测：`["热闹","空旷","寂静","夜晚","阴郁","雾"]`——**与 schema 完全一致**
- → **P5.2 的 VisualQuery 必须使用同一中文 token 空间**，否则 `includes()` 匹配恒 false。第一版不做自然语言（不引入 `visualIntentParser.js`），查询为手工构造的结构化对象

## 4. Personal Retrieval 最小设计（提案，待 STEP 1–3 实现）

### 4.1 新文件

```
src/services/memory/retrieveVisualMemory.js   （个人层新文件）
```

### 4.2 职责（唯一）

```
listMemories() 个人池（仅 status=success 且 intent.source≠"empty"）
    ↓
scoreIntent(queryIntent, candidateIntent)     ← 冻结，只组合
    ↓
排序（score 降序，过滤 score=0 或 reasons 空）
    ↓
返回 topK + evidence {memoryId, score, matchedFields, reasons}
```

**不做**：上传、Vision、存储、UI、检索去重规则、权重设计（全部复用冻结）。

### 4.3 需新增的最小派生（唯一新逻辑）

- `matchedFields(query, candidate)`：纯函数，遍历 VisualIntent schema 字段（**不读 WEIGHTS**），返回 `query[c]===candidate[c] && query[c]` 非空的字段名数组。~15 行，放 `retrieveVisualMemory.js` 内部。
- 检索准入过滤：`status === "success" && visualIntent.source !== "empty"`（P5.1.8 失败占位排除）+ `source !== "example"`（示例数据排除）——P5.1.8 契约已预留，此处只是消费该契约。

### 4.4 查询契约（STEP 1 预览）

```js
// VisualQuery = VisualIntent 子集（中文 token 空间，空字段不参与）
{
  atmosphere: ["寂静"],        // schema token
  colorTemperature: "cool",
  spatialDepth: "deep",
  negativeSpace: "high",
}
```

### 4.5 返回契约（STEP 2 预览）

```js
{ memoryId, score: 12.5, matchedFields: ["spatialDepth","negativeSpace"], reasons: ["纵深很深","留白很大"] }
```

## 6. 审计结论

**P5.2 Personal Retrieval 的最小实现范围成立**：

1. **数据就绪**：P5.1.8 的真实 20 条 success 记忆 + 中文 token 空间与 schema 一致（Q1 ✓）

3. **池隔离明确**：新模块只 import 冻结纯函数 + 个人层，两个池完全分开（Q3 ✓）
4. **验证目标正确**：第一版验证"能否用视觉语言找回自己的参考"而非准确率（Q4 ✓）

**实现范围建议（STEP 1–6）**：
- STEP 1 `src/services/memory/retrieveVisualMemory.js`（含 `matchedFields` 派生 + 准入过滤）
- STEP 2 QA `qa/memory/retrieval-test.mjs`（Case1 匹配 / Case2 无匹配诚实低分 / Case3 metadata 隔离 / Case4 failed 过滤）——零 mock 零 provider，用 P5.1.8 store 真实数据
- STEP 3 产品验证：3 个视觉语言查询在 20 条真实记忆上找回电影剧照/画作
- STEP 4 报告 `docs/P5.2.0-personal-retrieval-report.md`

**不进入实现的条件**：若审计发现评分不可组合/数据不可用/池隔离不可行——本次审计均未发现，**建议进入 STEP 1**。
