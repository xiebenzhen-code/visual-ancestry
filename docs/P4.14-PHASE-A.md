### A1.2 四个失败的定性（逐个查因，不是一起还原）

任务书要求区分四类。实测结论如下：

| # | 失败断言 | 定性 | 依据 |
|---|---|---|---|
| 1 | `sepia 单色相着色…` 理由不匹配 `/单色相着色/` | **真实分类函数缺陷** | `classifyChroma` 把「色相收窄」和「通道相关高」混在同一个分支，缺字段时先命中后者，理由写成 `通道相关高达 undefined` |
| 2 | `真彩色不被判成黑白` | **测试数据不完整** | 夹具 `{colorShare:0.71, hueSpreadDeg:36.3}` 写于第三条证据存在之前，没有 `minChannelCorrelation` |
| 3 | `低饱和度不足以判决` | **测试数据不完整** | 同上 |
| 4 | `远程门：…排除数应为 3，实际 4` | **测试数据不完整** | 该夹具用 `mk("d")` 造「彩色候选」，同样缺第三条证据 → 保守判黑白 → 4 条全排除 |

**没有一项属于「未完成实验引入的行为变化」**：新增的 `minChannelCorrelation` 本身在真实数据上是正确的（已知黑白 14 部 0.9810–1.0000，真彩色 0.3505–0.912）。问题在于判定函数的**理由分支顺序**，以及测试夹具没跟上新增的必填证据。

**也没有直接还原整个文件**：未提交的 90 行改动逐条保留。

### A1.3 处置

**（a）修真实缺陷 —— 理由按「最先失效的证据」给**

`src/services/retrieval/monochromePolicy.js`：

```js
const corrKnown = typeof chroma.minChannelCorrelation === "number";
const channelsIndependent = corrKnown && chroma.minChannelCorrelation < TH.maxChannelCorrelation;

if (hasColor && hueWide && channelsIndependent) → color
if (!hasColor)        → 实测黑白
if (!hueWide)         → 单色相着色（sepia/tint）
if (!corrKnown)       → 缺少通道相关证据，按排除处理
                      → 单色调映射（着色黑白）
```

关键点：**缺字段时不再冒充「实测相关高」**。判定上仍然排除（不默认放行），但理由必须诚实。

**（b）补测试夹具 —— 不改任何预期值**

四处夹具补上 `minChannelCorrelation`（远程门彩色候选 0.42、sepia 0.992、真彩色 0.7295、低饱和彩色 0.45）。**所有 `assert` 的期望值一字未改**，改的只是「让前提成立」的输入数据。

**（c）新增 4 项锁定用例（防回归）**

| 用例 | 锁的是什么 |
|---|---|
| 着色黑白：色相铺得开但通道同步 → 判黑白（Way Down East 04 实测 0.9102 / 27.9° / 0.9961） | P4.13 修的那个真实边界缺陷 |
| 缺少通道相关证据 → 不默认放行，且理由不得出现 `undefined` | 「未知状态不绕过排除」 |
| 两条着色路径给不同理由（sepia vs 青绿着色） | 理由分支顺序不被改回去 |

### A1.5 未解决的局限（如实登记）

`Gold Diggers of Broadway` (1929) 是 Technicolor Process 3（双色染印，不是俗称的 "two-strip"）彩色片。它与着色黑白重叠的原因不是扫描质量，而是工艺：双色 Technicolor 的色相天然在 8–13°，`minHueSpread: 25` 对它结构性不可达。**当前会被保守排除**。

**不通过调阈值修**：0.9521 与 0.9810 之间没有安全间隔，把阈值调到 0.97 会让判定依赖一个 0.02 宽的缝隙，换个扫描件就翻车。正确做法是给这类影片补**影片级已核实事实**（`FILM_COLOR_FACTS`），与现有架构一致。已登记为 `LIMIT`。
