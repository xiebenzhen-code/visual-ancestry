## 2. 凭据注入契约（已确认，接上就能用）

`server/vision/openaiProvider.mjs` 是唯一合法入口：

```js
export function serverVisionConfig(env = process.env, has = (n) => n !== undefined && n !== "") {
  return {
    endpoint: has(env.VISION_API_BASE) ? env.VISION_API_BASE : "",
    apiKey:    has(env.VISION_API_KEY) ? env.VISION_API_KEY : "",
    model:     has(env.VISION_MODEL)    ? env.VISION_MODEL : DEFAULT_MODEL,  // gpt-4o-mini
  };
}
export function visionConfigured(config) {
  return !!(config?.endpoint && config?.apiKey);
}
```

`scripts/server.mjs` 的 `POST /api/vision` 会在未配置时诚实返回 **503 `provider-not-configured`**，不伪造结果。

### 2.1 注入方式（严格遵守你的四条禁令）

```bash
# 仅在server 进程内注入，不落盘、不进 dist、不写日志
VISION_API_BASE="<endpoint>" VISION_API_KEY="<key>" VISION_MODEL="<model>" \
  node scripts/server.mjs dist 4175
```

| 禁令 | 如何满足 |
|---|---|
| 不写入仓库 | 只进进程环境变量，进程退出即消失 |
| 不进入 dist | 构建期不读`VISION_*`（`scripts/build.mjs` 反而把这三个名字列为**禁止出现在产物中的 token**） |
| 不生成 .env | 不创建任何文件 |
| 不保存日志 | 探针只输出 HTTP 状态与 schema 校验结果，不 dump 请求体/密钥 |

> 注：`build.mjs` 的泄漏扫描把 `VISION_API_KEY` 列为 forbidden token——即使误写进源码也会被构建拦截。这与P3.2 冻结基线的「layer1/layer2 CLEAN」一致。
