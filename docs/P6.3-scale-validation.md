## 1. 规模测试池的真实构成

```
scaleA = 500 条
  ├─ vision（真实 provider）       67 条   ← P6.2.1 三用户资产
  └─ rule-fallback（规则推导）    433 条   ← P6.3 外部博物馆资产
  渠道构成：电影 30 / 摄影 5 / 绘画 465

scaleB = 563 条（本环境最大真实规模）
  └─ 496 张外部馆藏 + 67 条已有资产，按 sha256 去重后
```

**为什么停在 563 而不是 1000**：外部三馆在本机网络下实际下载并通过校验的资产为 496 张（Small 100 + Medium 396 增量，去重后 496）。加上 P6.2.1 的可用资产，去重后共 563 个**不同的真实文件**。

**为什么不补齐到 1000**：`build-p63-archives.mjs` 显式拒绝重复：

```js
// scaleB < 1000 means the honest number of DISTINCT verified real files.
// Duplicating a file to reach a round number would make the scale test meaningless.
```

**500 条这个档位是真实达成的**，因此 §2 的性能数据是实测而非外推。

## 2. 性能：无退化，且可外推

实测缩放曲线（对真实 `scoreIntent` 逐条评分，5 次采样）：

**scaleA（最大 500 条）**

| 池大小 | avg | p50 | max |
|---|---|---|---|
| 10 | 0.271 ms | 0.151 ms | 0.802 ms |
| 50 | 0.652 ms | 0.495 ms | 1.122 ms |
| 100 | 0.929 ms | 0.883 ms | 1.340 ms |
| 200 | 0.578 ms | 0.561 ms | 0.663 ms |
| 400 | 1.177 ms | 1.157 ms | 1.265 ms |
| **500** | **1.540 ms** | **1.489 ms** | **1.676 ms** |

**scaleB（最大 563 条）**：500→563 时 avg 1.69 ms / max 1.873 ms。

**增长规律**：50→100→400→500 呈**线性**，约 **+2.7 µs/条**。中间点（200）偏低是因为该区间的外部资产 intent 字段更少，单条评分更快——这恰好说明**字段密度影响单条成本，池大小不是唯一变量**。

**外推到 1000 条**：按 2.7 µs/条 约 **2.7–3.5 ms**。相对 60–100 ms 的人类感知阈值仍有一个数量级余量。

> **诚实标注**：1000 条是**外推**，不是实测。563 条是本环境能达到的真实上限。要验证 1000 条，需先补vision 凭据把外部资产变成真实 intent（intent 字段更多 → 单条更慢），再扩大下载。**本阶段不把外推当实测。**

## 3. 无跨用户污染 / 无引用泄漏

### 3.1 隔离

三个池（artSmall 100 / filmArt 75 / artFilm 72 / mixed 66 / scaleA 167 / scaleB 167）**每个跑在独立 OS 进程中**。

> 依据 P6.2.1 的实测教训：`memoryRepository` 的 node 后端持有**模块级 `nodeState` 单例**，同进程内切换 `MEMORY_STORE_DIR` 会静默串户。本阶段一开始就采用进程隔离。

### 3.2 引用泄漏检查（最关键）

```
Assistant creative_support → 6 条引用
  allInPersonalPool: true
  foreignIds:        []
  allWithReason:     true
```

**6/6 引用全部来自该用户自己的池，且全部带 reason。** 没有任何一条指向池外资产，也没有引用其他用户的条目。

这是「本地优先个人记忆系统」的核心承诺：**别人的东西不会出现在你的档案里。**

## 4. Profile drift：显著，且已归因

### 4.1 实测漂移（P6.2.1 的 45 张 → P6.3 的 500 张）

| 指标 | 45 条 | 500 条 | 变化 |
|---|---|---|---|
| 深空间 | 67% |33% | **−34pt** |
| 环境主导 | 49% | 43% | −6pt |
| 强留白 | 22% | 29% | +7pt |
| 低饱和 | **89%** | **43%** | **−46pt** |
| 冷调 | 0% | 3% | +3pt |
| 暖调 | 40% | 6% | −34pt |
| 孤立人物 | **53%** | **8%** | **−45pt** |
| 静谧低唤醒 | 62% | 15% | −47pt |
| **confidence** | `tendency` | **`pattern`** | 阈值正确升级 |
| atmosphere 覆盖率 | 53% | **8%** | −45pt |

**这是本阶段最重要的产品发现。**

### 4.2 归因

**不是 bug，是新增数据的真实反映**：

- P6.2.1 的 45 张是**默片剧照为主**（30 电影 + 10 绘画 + 5 摄影）→默片天然低饱和、高孤立
- P6.3 新增的 433 张是**欧洲古典画作**（Oil on canvas / watercolor / engraving）→ 画作饱和度更高、题材更少人物

**孤立人物从 53% 掉到 8%**，因为 433 张风景/静物画里几乎没有人物。

**atmosphere 覆盖率从 53% 掉到 8%** 更加直接：规则回退**根本不产出 atmosphere token**，只有那 67 条真实 vision intent 里有。**43条 atmosphere token 的绝对数量没变（还是那批默片），但分母从 45 变成 500，比例塌到 8%。**

### 4.3 一个必须指出的次生效应

Profile 的诚实机制正确地把rule-fallback 的低产出标注了出来：

```json
"unavailable": {
  "emotion":     "仅 6/500 条有产出（1%），样本不足",
  "atmosphere":  "仅 41/500 条有产出（8%），样本不足",
  "composition": "冻结 Vision 层未产出该字段，无法呈现",
  "geometry":    "冻结 Vision 层未产出该字段，无法呈现"
}
```

`emotion` 产出率从 P6.2.1 的 13% 掉到 **1%**，因为规则回退**根本不产出 emotion**。产品没有把这 433 条的空白藏起来，而是明确告诉用户「样本不足」。**这是诚实机制在正常工作。**

### 4.4 对产品的启示

drift 本身合理，但**混合两种 intent 质量的池子会污染画像**。真实产品里这意味着：

> 用户从博物馆导入 400 张画作后，他原本的「低饱和 89%」会变成 43%，「孤立人物 53%」会变成 8%。**这些数字变化不是用户审美变了，而是导入方式变了。**

更严重的是：Assistant 的 `narrative` 字段**直接变空**了——因为没有任何叙事倾向达到展示阈值。用户问「我存的这些图有什么共同倾向」，得到的答案从三条萎缩到两条。

**P6.4 必须处理**：导入外部资产时提示「这批尚未经识图，画像可能不准确」，或对 rule-fallback 资产在画像统计中降权/ 排除。

## 5. Assistant 在规模下的行为

```
references: 6条 · allInPersonalPool: true · allWithReason: true
direction:
  space:       环境主导构图（52%）、深空间（49%）
  composition: 远景镜头（46%）
  color:       低饱和（52%）
  narrative:   （空 —— 孤立人物仅 23%，未达展示阈值）
```

**`narrative` 为空是正确的诚实行为**：孤立人物比例掉到 23% 后，profile 不再把它当作一个「倾向」展示。P6.2.1 时是 53%，会展示「孤立人物（53%）」。
