# P6.3.1 — 安全缺口登记：bridge 缺少 schema 校验门禁

**登记日期**：2026-10-07
**状态**：**仅登记，本轮不修复**
**关联**：P6.3.1 Provider Gate（`NOT_READY`）—— 但本缺口**独立于** provider 根因定位
**修复前置条件**：待 Provider 根因定位后，单独建立 schema-validation gate

---

## 1. 缺口描述

`scripts/server.mjs:121` 将 provider 返回的 parsed raw JSON **原样**作为 intent 交给客户端：

```js
sendJson(res, 200, { ok: true, intent: result.raw, latencyMs: result.latencyMs ?? null });
```

`result.raw` 来自 `server/vision/openaiProvider.mjs:200`：

```js
raw = JSON.parse(stripFence(content));
```

**中间没有任何 schema 校验、白名单过滤或字段归一化。**

---

## 2. 风险

只要 provider 返回的 JSON **语法合法**，无论字段名多么离谱，客户端都会收到
`HTTP 200` + `ok: true` + 一个不符合VisualIntent 契约的 intent。

### 2.1 本轮已实证发生

`work/p6.3.1c/smoke/contract-probe.json` 记录了真实发生的案例：

```json
HTTP 200
{"ok":true,
 "intent":{"subject_type":null,"body_part_visible":null,"spatial_arrangement":null,
           "interaction":null,"scene_type":null,"weather":null,"setting":null,
           "text_visible":null,"face_visibility":null,"visual_style":null},
 "latencyMs":11624}
```

- provider 返回字段与冻结 schema **零交集**（10 个自创字段 vs 22 个契约字段）
- bridge 仍然判定成功并返回 200 / `ok:true`
- 若非探针比对字段名，这个错误 intent 会被当作合法结果消费

### 2.2 下游影响面

| 消费方 | 误判后果 |
|---|---|
| `normalizeVisionIntent` 白名单 | 全部字段被丢弃 → intent 变空对象 |
| 冻结检索评分器 `scoring.js` | 所有视觉字段缺失 → 检索退化为无视觉依据的排序 |
| 画像 `visualProfile.js` | 基于空/错intent 统计，污染 profile |
| Assistant `visualAssistant.js` | grounding 依据失真，存在泄漏风险 |

**严重性**：`scoring.js` 与 `visualProfile.js` 是冻结核心，
它们**信任** intent 的合法性。校验责任本应在 bridge，一旦缺失，
**错误数据会静默流入冻结模块**，且从检索结果上不可见。

---

## 3. 为什么现在不修

1. **修复位置在bridge 内**（`openaiProvider.mjs` 或 `server.mjs`），
   与本轮「禁止修改 bridge」的约束冲突。
2. **根因未定**：若 provider 根因是模型不可靠，那么「拒绝非法 schema」只是
   把错误变成错误响应，不恢复能力；需要先确定能力边界再定校验严格程度。
3. **不能误伤正常路径**：校验过严可能把上游「本可接受的偏差」也拒掉，
   在provider 行为未稳定前难以标定阈值。

---

## 4. 待办（根因定位后单独立项）

建议的 schema-validation gate 设计要点，**供后续立项参考，尚未实施**：

| 要点 | 说明 |
|---|---|
| 校验位置 | bridge 内，`JSON.parse` 之后、返回客户端之前 |
| 校验内容 | 字段名集合 ⊆/== schema `properties`；类型匹配；枚举值在枚举内 |
| 失败行为 | 返回**非 200 + 机器可读 code**，而非 `ok:true` + 错误 intent |
| 部分缺失 | 区分「字段错位」（拒绝）与「字段为 null」（合法，schema 允许 null） |
| 与冻结核心的边界 | 校验只在 bridge，**不触碰** `scoring.js` / `visualProfile.js` |
| 可观测性 | 记录被拒响应的字段名并集，便于定位 provider 行为漂移 |
