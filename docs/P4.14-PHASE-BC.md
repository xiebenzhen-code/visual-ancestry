## 2. 新旧媒介分类映射

### 2.1 四层定义

| 层 | 取值 | 说明 |
|---|---|---|
| `medium` | `artwork` / `film` | **旧枚举，只读不改**。8 处代码字符串直比它 |
| `visualForm` | `live-action` / `animation` / `still-image` / `unknown` | 真人还是动画 |
| `tradition` | 有证据的创作传统（`anime` / `romanticism` / `ukiyo-e` …） | **只能来自数据声明** |
| `imageKind` | `frame` / `scene-still` / `publicity-still` / `publicity-photo` / `artwork-reproduction` / `poster` / `unknown` | 这张图是什么 |

### 2.2 旧数据如何映射（不做数据迁移）

| 旧记录 | medium | visualForm | tradition | imageKind | 依据 |
|---|---|---|---|---|---|
| 46 件本地绘画（无 `medium` 字段） | `artwork` | `still-image` | 取 `traditions[0]` | `artwork-reproduction` | 缺省即 artwork，与 `retrievalService.js:245` 一致 |
| 15 部本地影片 | `film` | `live-action` | `null` | 沿用原字段（`frame` 5 / `scene-still` 7 / `publicity-*` 3） | 影片级事实表 `FILM_VISUAL_FORM_FACTS` |
| 未来动画 | `film` | `animation` | 有证据时 `anime` | `frame` | 必须声明，不许推断 |

### 2.3 三个反直觉的地方（都写进了测试）

1. **影片的 `traditions: ["电影"]` 不是创作传统。** 那是媒介名。原样透传会得出「这部片属于电影传统」的同义反复。已列入 `NON_TRADITION_LABELS` 排除。
2. **`medium:"film"` 不能推出 `visualForm:"live-action"`。** 电影可以是动画。表里没有的影片一律 `unknown`，不是 `live-action`——否则将来接入动画片会被默认错标。
3. **`anime` 必须是「animation + 有证据的传统」同时成立。** 只有 tradition 没有 visualForm 不算；两者都没有更不算。

### 2.4 兼容护栏（可执行）

```js
assertLegacyMedium("artwork")   // { ok: true }
assertLegacyMedium("film")      // { ok: true }
assertLegacyMedium("animation") // { ok: false }
assertLegacyMedium("anime")     // { ok: false }
```

新增层次一律走派生字段，**不得塞回 `medium`**。

|---|---|

| `rights` | `unknownRights()`——显式表达「不知道」 |
| `visual` | `makeVisualEvidence({})`——`level: "none"` |

### 3.2 四状态由证据推出（不是调用方指定）

| 状态 | 判据 |
|---|---|
| `METADATA_ONLY` | 无 `imageURL`，或图像**明确解码失败** |
| `IMAGE_AVAILABLE` | 有图像、未明确失败，但**没有视觉特征** |
| `VISUAL_ANALYZED` | 有视觉特征，但许可/政策/图像验证不满足 |
| `RECOMMENDABLE` | 五项同时成立：图像 + **已验证解码** + 许可 confirmed + 非黑白排除 + 是实际画面 + 有视觉证据 |

**关键：未分析的真实馆藏图停在 `IMAGE_AVAILABLE`，不是被永久排除。** 四馆现在全部在这一档——这是正确的，等着后续合法的视觉特征计算。

## 4. 权利判断矩阵（四馆 + Commons）

### 4.1 先纠正一个前提

四个 adapter **不输出 `showable`**，只输出 `publicDomain`。`showable` 是在消费端算出来的：

```js
// remoteDiscovery.js:923
showable: Boolean(w.publicDomain) && Boolean(w.image?.url)
// remoteDiscovery.js:720（Commons）
rights.showable ? { ...base, showable: true } : { ...base, showable: false }
```

所以病灶不是「四个 showable 不一致」，而是**同一个 `publicDomain` 在四个 adapter 里各算了一件不同的事**，Commons 又在另一处用另一套条件算出同名产物。

### 4.2 六个维度分开判

| 来源 | 图片来源 | 作品权利 | 展示许可 | 缓存/再分发 | 结论由谁支持 | 取得时机 |
|---|---|---|---|---|---|---|
| Rijksmuseum | 明确（IIIF） | 明确（PDM 1.0） | 允许 | **允许** | provider-field | runtime |
| Met | 明确 | 明确（`isPublicDomain`） | 允许 | **未知** | our-inference | runtime |
| AIC | 明确 | 明确（`is_public_domain`） | 允许 | **未知** | our-inference | runtime |
| Cleveland | 明确 | 明确（CC0） | 允许 | **允许** | provider-field | runtime |
| Commons | 明确 | 明确（extmetadata） | 允许 | 允许 | provider-field | runtime |

四馆许可陈述原文（实测）：

| 来源 | `rights` 字段实际值 | `publicDomain` |
|---|---|---|
| Rijks | `creativecommons.org/publicdomain/mark/1.0/ (Rijksmuseum)` | `true` |
| Met | `Public domain` | `true` |
| AIC | `Public domain` | `true` |
| Cleveland | `CC0 (Cleveland Museum of Art)` | `true` |

**Met 与 AIC 的「Public domain」只说明作品版权状态，没有对图像再分发作出明示授权。** 因此契约里 `cacheRedistributionAllowed = unknown`，`verdict = unconfirmed` —— 它们**不能**升到 `RECOMMENDABLE`。这正是把「未知」与「已确认」分开的价值。

## 5. 动画 / 动漫来源能力矩阵

| 来源 | 日本动漫元数据 | 实际动画帧 | 只有海报 | 可访问可解码 | 公开产品展示 | 缓存再分发 | 镜头级视觉信息 | 结论 |
|---|---|---|---|---|---|---|---|---|
| **Wikimedia Commons** | 无结构化字段 | **有，仅公版区（约 1914–1929）** | 否 | 是 | 允许（PD） | 允许 | 有，但样本极少 | **ACCEPT（范围极窄）** |
| **Openverse** | 少 | 有（依赖上游） | 部分 | 是 | 依上游许可 | 依上游 | 有限 | **EXPERIMENTAL** |
| **Internet Archive** | 有 | 有 `.thumbs/`（约每秒 1 帧） | 否 | 是 | 依条目 | 依条目 | **分辨率仅 160×110，撑不起构图比较** | **EXPERIMENTAL** |
| **AniList** | **有（事实字段）** | 无 | 只有封面 | 封面可访问 | 封面禁用 | 否 | 无 | **METADATA_ONLY** |
| **TMDB** | 有 | 无（图片需授权） | 是 | — | 受限 | 否 | 无 | **REJECT** |

### 5.1 最重要的结论

**没有任何一个来源能提供受版权保护的现代日本动漫正片帧。**

- 可解码、可展示、可再分发的动画帧只存在于**公版区间（约 1914–1929）**，数量以「单帧/单文件」计，不成体系。
- 且这些公版动画**全部是黑白的**（`mode=L`）——按 P4.12 规则本来就进不了 AIGC 参考。
- 例外：Internet Archive 的 `.thumbs/` 是唯一「接近镜头级」的合法取样路径，但 160×110 无法支撑构图比较。

**因此 PHASE C 的答案是：动漫帧这一格填不上，如实留空。** 不用海报冒充镜头，不为填满类别接入无关作品。

## 6. 真实样本与可用性证据（STEP 2 验收）

四馆各一条真实记录 + 一个本地影片 + 一个 Commons 动态候选，**每张图用 sharp 实际解码**：

| 来源 | 记录 | 解码 | 尺寸 | visualForm | imageKind | 许可 | 状态 |
|---|---|---|---|---|---|---|---|
| Rijksmuseum | Landscape with a Stone Bridge | ✅ jpeg | 960×676 | still-image | artwork-reproduction | confirmed | `image-available` |
| Met | Landscape (recto); Landscape (verso) | ✅ jpeg | 3634×2661 | still-image | artwork-reproduction | unconfirmed | `image-available` |
| AIC | Village Among the Trees | ❌ **HTTP 403** | — | still-image | artwork-reproduction | unconfirmed | `metadata-only` |
| Cleveland | Virgin and Child in a Landscape | ✅ jpeg | 1536×1931 | still-image | artwork-reproduction | confirmed | `image-available` |
| 本地影片 | 海逝（`film-toll-of-the-sea`） | ✅ webp | 1920×1421 | live-action | frame | confirmed | **`recommendable`** |
| Commons | Still from Gold Diggers of Broadway | ✅ jpeg | 1916×1080 | live-action | scene-still | confirmed | `image-available` |

**两个真实发现：**

1. **AIC 图片返回 HTTP 403。** 记录有 `image_id`、URL 也拼得出来，但 CDN 拒绝。按契约它退回 `metadata-only`——如果只看「有没有 URL」，这条会被误报成可用图像。这是「HTTP 200 不算证据」这条规则第一次真的抓到东西。
2. **四馆全部停在 `image-available`。** 因为 `analysisLevel = 0`，没有任何视觉特征。它们**不应**出现在视觉相似推荐里，但仍是合法的元数据与图像线索。

## 7. Gold Diggers 核验结果（STEP 4）

**结论：维持保守排除。不补影片级事实。**

### 7.1 影片事实站得住

彩色工艺是 **Technicolor Process 3**（双色染料转印/imbibition），**不是**俗称的 "two-strip"。维基百科条目 `color_process = Technicolor Process 3`，原文：

> the system Technicolor used at that time was a subtractive imbibition two-color process introduced in 1928 … as opposed to two prints cemented together, as had previously been the case.

工艺名要写准，因为 `basis` 字段会**原样出现在用户可见的理由里**。

### 7.2 但这张图证明不了原生彩色

- 该 Commons 文件的来源是一个 **X 帖子**，画幅 **16:9**。
- 无法证明它是从彩色拷贝扫来的。
- 因此「这张图是否有原生彩色信息」——**证据不足**。

### 7.3 比「扫描件偏暗」更根本的原因

我此前在 P4.13 / P4.14-A 里写的归因是**错的**：不是「16mm 扫描件偏暗、颗粒重」。

真正的原因是**工艺**：双色 Technicolor 只有红橙与青绿两条染料记录，色相天然收缩。实测四张该片素材（含两张明确标注「存世拷贝帧」的 4:3 图）分别是 **10.7° / 12.3° / 13° / 8°**，全部卡在 `minHueSpread: 25` 之下。

**这条判据对双色 Technicolor 结构性不可达，不是个案。** 三处文档已按此改写。

### 7.4 关键：补事实对远程候选零效果

即使给 Gold Diggers 补一条 `FILM_COLOR_FACTS`，**对这条远程候选也不起作用**：

- `judgeFilmCandidate`（`monochromePolicy.js:238`）确实会短路、不读像素（`:253-267`）；
- 但远程路径 `remoteReferences.js:363` 调的是 `gateRemoteFilmByColor`，它（`filmColorGate.js:140`）**直接 `classifyChroma`，从不 import `FILM_COLOR_FACTS`**；
- 而且键值也对不上：远程 id 是 `remote-film:${sourceId}`，与 `film-*` 命名空间不同。

所以要让它生效，必须先**改远程门控接受影片级事实**——那是设计变更，不是数据补充。本轮**不做**。

| 项 | 决定 |
|---|---|

| 补 `FILM_COLOR_FACTS` | **不补**（对远程零效果，且证据不足） |

## 11. 给下一轮的判断材料

任务书要求「停止，提交报告供用户判断下一轮应该采用哪些来源和哪些视觉关系特征」。以下是事实，不是建议：

**来源侧**

- 四馆都是**元数据级**资产，不是视觉参考源。把它们的图纳入视觉相似推荐前，必须先有合法的视觉特征计算。
- 开放数据侧的动漫是死路。要动漫，只能走授权。
- 公版动画（1914–1929）虽然拿得到，但**全是黑白的**，与 P4.12 冲突。

**特征侧**

- P4.13-R / P4.13-F 已证明：三套加权方案都无法改变 `birth-of-venus` 排名第一，两条向量碰撞无法靠调权解除。
- 缺的维度是：画幅方向、构图骨架、人数主次、道具、场景类型。
- 其中 `artwork.orientation`、`artwork.medium`、`artwork.year`、`artwork.culture` **已在数据库中，从未进入 intent**；`composition` 策展散文 **51/51 都有**，也从未进入 intent。

这三条是 PHASE D 的最低成本起点。
