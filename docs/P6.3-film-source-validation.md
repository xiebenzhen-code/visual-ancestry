## 3. 为什么不复制电影数据库

P6.3 的核心原则是「电影不能复制电影数据库」。本阶段用两条路径证明了这一点：

```
Path A（公共来源）      →  证明素材可规模化获取与溯源
Path B（用户导入）      →  证明产品方向可行：用户自己的截图就是入口
```

**用户不需要产品内置一个电影库**。用户想的是「我记得《尼伯龙根的指环》里那个把人物压得很小的镜头」——Path B 让这个检索成立，且引用的是**他自己保存过的那张图**。

这与P6.2.1 的结论一致：结果由个人池决定，不是数据库回声。

### 4.1 电影来源的真实路径缺口（重要结论）

Path A 证明的是「**公版默片/早期片**有稳定来源」，而这恰恰是版权最清晰、最不适合现代观众兴趣的区间。

**真实的电影视觉资产来源只有三条路**：

| 路径 | 可行性 | 说明 |
|---|---|---|
| 用户自己截图 | ✅ **已验证**（Path B） | TMDB 等API **不提供剧照图片**，只给海报路径；本项目不内置电影库是**正确的**产品判断 |
| 公版片库 | ⚠️ 有限 | Wikimedia/Internet Archive 主要是默片 |
| 授权片库 | ❌ 未探索 | 商业授权是法务与成本问题，本阶段不碰 |

**给 P6.4 的建议**：电影方向的正确产品定位是「**用户自己收藏的剧照**」，而不是「产品提供一个电影库」。Path B 已经证明这条路成立。
