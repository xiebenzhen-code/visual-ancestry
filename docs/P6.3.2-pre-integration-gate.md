## STEP 4 · 日志安全设计

### 4.1 审计发现

`violations[].detail` **确实含用户派生内容**：

```
R4a: invalid type: saturation=999
R6:  atmosphere: "晴天"
R3:  unexpected keys: weather
```

这些值源自用户上传图片的模型输出 → **禁止进日志、禁止回传客户端**。

### 4.2 安全设计

| 层级 | 允许内容 | 禁止内容 |
|---|---|---|
| **日志** | `code` · `rulesTriggered`（规则名）· `ruleCounts`（计数）| ❌ `violations[].detail` · ❌ 原始响应 · ❌ 用户数据 |
| **客户端响应** | `error.code` + 通用 `message` | ❌ violations 任何内容 |
| **`violations`** | 仅进程内断言使用 | ❌ 任何外流 |

### 4.3 安全日志示例（唯一允许形态）

```json
{
  "code": "intent-missing-fields",
  "ruleCounts": { "R2": 1, "R3": 1, "R4a": 1, "R6": 1 },
  "violationCount": 4,
  "rulesTriggered": ["R2", "R3", "R4a", "R6"]
}
```

客户端响应：

```json
{ "error": { "code": "intent-missing-fields", "message": "VisualIntent V1 校验失败（4 项）。" } }
```

**两者均不含任何 provider 返回的值。**

### 4.4 修复 E08 不得引入新 E15

⚠ 当前 `openaiProvider.mjs:158-162` 的 `[vision-debug]` **直接打印上游响应前 200 字符**，
本身已违反此策略。接入 validator 时**必须同时移除它**，否则等于修 E08 又造 E15。
