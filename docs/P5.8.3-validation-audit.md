## 4. 四项确认（spec 要求）

1. **测试池来源**：既有素材 32 张（电影 16 / 绘画 16）+ Wikimedia 公版新下载（约 38 张：默片剧照 14、东方绘画 4、公版摄影 20）。**真实 vision 已验证可用**——4175 常驻服务进程持有 provider 凭据，探测请求 HTTP 200 返回完整 intent（arousal/atmosphere/cameraDistance/humanRelation 等全字段）。注意：凭据仅在服务进程，测试脚本一律走 `http://127.0.0.1:4175/api/vision`（与既有 QA 相同路径），仓库与测试脚本中零凭据。
2. **当前支持图片类型**：JPG/PNG/WEBP/GIF，单张 ≤6MB，一次 ≤50 张；入库时 canvas 缩略 420px JPEG q0.72（原图不持久化）。
3. **当前跨媒介能力**：origin 枚举含 film-still/artwork-reference/photo/ai-generated/user-upload；混排检索已在 P5.5 Case 2（跨媒介 top1 非同媒介）与 P5.7 跨项目验证（Film+Painting+Personal 同一视觉语言空间）通过。
4. **当前限制**（诚实清单）：
   - sharedReasons 标签表冻结：humanRelation/colorTemperature/emotion 非标签字段不能单独作查询条件（score>0 但 reasons=0 会被拒收）——检索案例设计须至少含一个 reason-labeled 字段
   - 生产 browser localStorage 5MB ≈ 127 条；本测试走 Node 隔离 store 无此限制，但 C 用户 60 条的数据规模本身即是容量语义验证点
   - real provider 依赖 4175 常驻进程存活；`upload-reliability-backtest` 类全量真实套件在批量大时会挂起（P5.8.2 教训）——本阶段测试脚本必须带单请求超时 + 逐张重试 + 增量落盘
   - Assistant 的 ENRICHABLE 补全仅限 reason-labeled 字段（P5.6 冻结纪律延续）
