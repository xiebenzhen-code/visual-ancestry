## 2. 缺陷一：三源均衡度失控

### 现象

**本轮 997 张全部来自 Met，AIC 与 Rijks 各 0 张。**

### 根因

脚本按顺序跑三个源，每个源用 `need()` 判断是否已满：

```js
for (const q of MET_QUERIES) { if (need() <= 0) break; ... }  // Met 跑满
for (const q of AIC_QUERIES)  { if (need() <= 0) break; ... }  // 立即跳出
```

Met 的 30 个 query 每个最多返回 100 条，**仅前 10 个 query 就吃满 1000 预算**，后两个源完全没机会。

### 影响

磁盘总量仍是 1669 张（三源都有），但**新增部分单一来源**，会削弱「多源泛化」这一轮的验证价值——如果用新增的 997 张建池做检索测试，结论会偏向 Met 的馆藏结构。

### 正确做法

```js
// 按源分配预算，而非顺序吃满
const perSource = Math.ceil(need() / 3);
for (const q of MET_QUERIES)  { if (gotFrom('met')  >= perSource) break; ... }
for (const q of AIC_QUERIES)  { if (gotFrom('aic')  >= perSource) break; ... }
for (const c of RIJKS_CREATORS) { if (gotFrom('rijks') >= perSource) break; ... }
```

**未修正的原因**：本轮目标是「数量达标」，已达成。修正需要重跑（约 50 分钟），而 vision 凭据未到位时这些资产也无法进入检索验证。**记录为 P6.4 的第一个修正项。**

## 3. 缺陷二：语义多样性不足

### 实测

```
997 张 → 761 个不同标题 → 标题重复率 23.7%
泛化标题（study / sketch / drawing / design for）189 张 = 19.0%
```

重复最多的标题：

| 次数 | 标题 |
|---|---|
| 51× | *landscape* |
| 29× | *self-portrait* |
| 13× | *battle scene* |
| 9× | *landscape with figures* |
| 7× | *river scene* / *harbor scene* / *horse* / *study of a hand* |

### 为什么会这样

**sha256 去重拦不住语义重复。** 51 张 *landscape* 是**不同的画**（不同 sha256），只是标题都叫 *landscape*。它们全部通过了去重与 metadata 门禁。

**根因是查询词太宽**：`landscape` / `study` / `sketch` / `drawing` 这类词在 Met 的库藏里返回大量同名系列作品。

### 影响

数量达标，但**这批资产的视觉语言分布是偏斜的**。若用它建池：
- 检索测试会偏向「风景/素描」类query
- 画像统计会被19% 的泛化素描拉偏
- 「跨媒介/跨时代」的验证力度下降

### 正确做法

```js
// 1. 标题去重（保留 sha256 不同的第一张）
const seenTitles = new Set();
if (seenTitles.has(titleKey)) continue;   // 同一标题只收1 张

// 2. 排除泛化类别
const GENERIC = /^(study|studies|sketch|drawing|design for|untitled|sheet of|album)\b/i;
if (GENERIC.test(title)) continue;          // 或降权

// 3. 查询词用具体题材而非体裁
"landscape" → "landscape with waterfall" / "mountain landscape" / "seascape"
```

**这也是 P6.2.1 里`spread-pick` 想解决但没解决干净的问题** —— 那时我按 intent signature 做了 spread，但**没有对标题做语义去重**。

## 4. 我在 STEP 2 刚写下的教训，在这里再次应验

STEP 2 的剧照审计让我写下：

> **每个新增数据源都要问「我验证的维度和我声称的维度是同一个吗」**

**本轮的两个缺陷正是这句话的两种表现**：

| 声称 | 实际验证的 | 差距 |
|---|---|---|
| 「1000 张绘画」 | ✅ 1000 张真实图片 + 完整 metadata | 无—— 这一项是真达标 |
| 「多源接入」 | ✅ 三源都接通了 | 但本轮新增全来自 Met |
| （隐含）「视觉语言多样的测试池」 | ❌ 只验证了数量与 metadata | 标题重复率 23.7% |

**前两项我验证了，第三项我默认了。**
