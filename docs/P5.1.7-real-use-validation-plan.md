## 3. 测试流程（Steps）

```
STEP 1  准备素材（A 类下载 + C 类抽取）→ work/p5.1.7-materials/{A-film,C-art}
STEP 2  真实上传：每张 → Memory Upload 链路（/api/vision 真实 provider）→ 保存
        （隔离存储 MEMORY_STORE_DIR=work/p5.1.7-store，不污染产品数据）
        逐张记录：耗时、AI intent vs 图片内容 → Q2 三问 + 价值评级
STEP 3  资产浏览：20+ 张后浏览 Memory 首页
        → 统计 visualIntent 分布（个人视觉倾向是否浮现）
        → 判断首页像 A 图片文件夹 or B 个人视觉库
STEP 4  二次使用：隔时段重新打开，不看文件名，尝试找
        「孤独城市镜头 / 荒原环境 / 低饱和夜景」参考
        → 记录当前产品是否支持找到；不能则记录"需要什么能力"
STEP 5  需求归类：所有问题归入 A 数据输入 / B 理解 / C 组织 / D 创作
STEP 6  输出 docs/P5.1.7-real-use-validation-report.md
STEP 7  按决策规则选择下一步方向（P5.2 Retrieval / Aesthetic Profile / Batch Import / Project Moodboard）
```

## 4. 观察指标

### 上传体验
- 单张是否麻烦（表单步骤数）
- 是否需要批量（连续 20+ 张时的摩擦）
- 等待时间（每张 latency 实测；20+ 张累计时长）

### AI 输出质量（每张，Q2）
- A：是否描述出了喜欢的东西？（是/否 + 证据）
- B：是否出现明显废话？（是/否 + 例）
- C：是否发现没注意到的视觉关系？（是/否 + 例）
- 价值评级：高 / 中 / 低（对"超越文件夹"的贡献，不是通用质量分）

### 浏览（Q1 相关）
- 视觉倾向是否浮现（大量低饱和/远景/孤独人物/环境压迫…）
- 首页感知：A 图片文件夹 or B 个人视觉库（原因）

### 二次使用（Q3）
- 三个参考需求是否被现有产品支持
- 失败时记录的"需要能力"原始描述

## 5. 成功 / 诚实失败判定

- 素材下载失败（某类不足）→ 记录可用素材，标注限制，**不伪造**
- 某张上传失败（provider 502/503）→ 如实记录，不重试（延续 provider 纪律），计入失败率
- B 类（AIGC/自己作品）无用户素材 → 明确记录"本阶段未验证"，结论不夸大
- 最终输出状态：`P5.1.7 REAL USE VALIDATION COMPLETE`（若 A+C 真实链路完成 + 报告输出）
