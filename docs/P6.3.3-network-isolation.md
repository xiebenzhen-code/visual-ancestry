## 4. 最小 diff 提案（等待批准，未执行）

### 方案 A（推荐）：单行硬编码回环
```diff
--- a/visual-ancestry/scripts/server.mjs（blob c884b04e）
+++ b/visual-ancestry/scripts/server.mjs
-  server.listen(port, () => {
+  server.listen(port, "127.0.0.1", () => {
```
- 位置：`:166`；改动 1 行。
- 效果：只监听 IPv4 回环，不再产生 `[::]` 绑定；Windows 上显式 host 时不启用 dual-stack。
- 优点：硬默认安全，**不存在** HOST 环境变量被误设成 `0.0.0.0` 的逃逸路径。

### 方案 B：支持环境变量覆盖（备用）
```diff
@@ :9（紧邻 requestedPort）
+ const requestedHost = process.env.HOST || "127.0.0.1";
@@ :166
-  server.listen(port, () => {
+  server.listen(port, requestedHost, () => {
```
- 改动 2 行；默认仍安全，为将来「受信内网联调」留后门（需显式 `HOST=0.0.0.0`）。
- 缺点：多一个可被误配的开关，与 fail-closed 哲学略有出入。

**建议：方案 A**。若批准，应用后依次执行 §5 回归验证。
