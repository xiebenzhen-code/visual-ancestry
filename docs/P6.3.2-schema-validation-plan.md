### 1.2 契约不一致（**精确统计，已纠正**）

**实测数据**（从源码逐项提取，非推断）：

| 契约 | 位置 | 字段数 |

> ⚠ 本文档早期版本写「24 / 25」，**24 是错的**（漏计 `source`）。以下为实测值。

| 项 | 数量 | 字段 |
|---|---|---|

| 字段 | 在 wire | 在 internal | 性质 |
|---|---|---|---|
| 22 个 schema 字段 | ✅ | ✅ | 一致 |

| `geometry` | ❌ | ✅ | 同上 |

**Validator 必填清单必须按 wire 的 22 个**（provider 的实际输出契约）。

若按 internal 的 25 个校验，**所有 provider 返回都会被判「缺失 3 字段」而全量拒绝**。

**两份 raw 样本**：

| 文件 | 路径 | keys | 22 齐全 | validator 判定 |
|---|---|---|---|---|

## STEP 2 · 相关文件核对

### 2.1 `scripts/server.mjs`（bridge，**冻结** sha256 `e8859d715fd2a503`）

插入点（`:114-121`）：

```js
const blob = new Blob([bytes], { type: mimeType });
try {
  const result = await provider.callVisionProvider(blob, config, { timeoutMs: 60_000 });
  if (!result.ok) {
    sendJson(res, 502, { error: { code: result.reason || "vision-failed", ... } });
    return;
  }
  sendJson(res, 200, { ok: true, intent: result.raw, latencyMs: ... });   // ← 校验插入点
} catch (err) { ... }
```

**当前行为 = fail open**：`result.raw` 原样透传（E08）。

已有的前置校验（**保留，不动**）：

| 检查 | 行号 | 行为 |
|---|---|---|
| `imageBase64` + `mimeType` 必填 | `:70` | 400 `missing-field` |
| MIME 白名单 | `:74` | 400 `unsupported-format` |
| base64 字母表 + 长度 % 4 | `:82` | 400 `invalid-base64` |
| body 上限 6 MB | `:54` | 413 `payload-too-large` |

### 2.2 `server/vision/openaiProvider.mjs`（**冻结** sha256 `96583b6e367eb490`）

成功路径（`:260`）：`return { ok: true, raw, latencyMs }`
其中 `raw = JSON.parse(stripFence(content))`（`:200`）—— **已是解析后的对象**。

**推论**：validator 接收到的必然是对象，**不需要**重复 `JSON.parse`。
但需防御非对象（数组 / null / 原始值）。

失败路径已分类完备（`auth` / `quota` / `server` / `request` /
`transport-invalid` / `invalid-json` / `empty-response` / `timeout` / `network`）。

**validator 不应修改此文件** —— 它已把「无法解析」与「解析成功但结构错」
区分开（`invalid-json` vs `ok:true`）。后者正是 validator 要补的缺口。

### 2.3 `src/services/vision/normalizeVisionIntent.js`（浏览器侧，**非冻结**）

```js
:43  return allowed.includes(value) ? value : "";                    // 非法枚举 → ""
:50  for (const [field, allowed] of Object.entries(ENUMS)) {
:51    const value = keep(raw[field], allowed);
:52    if (value) patch[field] = value;                             // 丢弃非法
:55    const list = Array.isArray(raw[field]) ? raw[field].filter(...) : [];
:58  return mergeIntent(emptyVisualIntent(), patch);                // 补齐缺失
```

**这是 fail-open 清洗器**，行为与 validator 完全相反：

| 行为 | normalizeVisionIntent | validator 要求 |
|---|---|---|
| 非法枚举 | 静默丢弃（`""`） | **拒绝** |
| 缺失字段 | `emptyVisualIntent()` 补齐 | **拒绝** |
| 额外字段 | 忽略 | **拒绝** |
| 非数组 | 置 `[]` | **拒绝** |

**结论**：validator 必须在 **server侧**（`server.mjs`），
让错误在到达浏览器前就被拦下。不能依赖浏览器侧清洗 ——
那正是 E08「错误静默流入」的路径。

### 2.4 `work/p6.3.1c/provider-smoke.mjs`（E09）

```js
:180  row.schemaValid = !!(intent && intent.source === "vision" && present.length >= 6 && unknown.length === 0);
```

**已知失效**（E09）：要求 `intent.source === "vision"`，
但 bridge 不注入该字段（由浏览器侧 `normalizeVisionIntent.js:49` 注入）。
且 `SCHEMA_FIELDS` 多列 `composition` / `geometry` / `source` → `unknown.length !== 0`。

**实施时需同步修正**，否则 smoke 会把合法结果判为失败。

## STEP 3 · 最小独立 validator 设计

### 3.1 位置与形态

| 项 | 设计 |
|---|---|
| 文件 | **新建** `server/vision/visualIntentValidator.mjs`（**不改冻结文件**）|
| 导出 | `validateVisualIntent(raw)` → `{ ok, code, message, violations }` |
| 纯函数 | 无 I/O、无 env、无网络 |
| 依赖 | 契约常量**从 `openaiProvider.mjs` 导入**或独立声明（见 3.4）|

### 3.2 七条规则（fail closed）

| # | 规则 | 违反时 |
|---|---|---|
| 1 | `raw` 是非数组对象 | `not-an-object` |
| 2 | **22 个 required 字段全部存在** | `missing-fields` |
| 3 | 无 schema 外字段（`additionalProperties: false`）| `unexpected-fields` |
| 4 | 20 个 enum 字段：`null` 或 string且 ∈ 对应枚举 | `invalid-type` / `invalid-enum` |
| 5 | `emotion`/`atmosphere`：Array、length ≤ 3 | `invalid-type` / `too-many-items` |
| 6 | 列表每项 ∈ token whitelist | `invalid-token` |
| 7 | **禁止自动补齐** —— 缺失即拒绝，不填 null | `missing-fields` |

### 3.3 机器可读错误码

| code | HTTP | 含义 |
|---|---|---|
| `intent-not-an-object` | 502 | 上游返回非对象 |
| `intent-missing-fields` | 502 | 缺必填字段 |
| `intent-unexpected-fields` | 502 | 含 schema 外字段 |
| `intent-invalid-type` | 502 | 字段类型错 |
| `intent-invalid-enum` | 502 | 枚举值非法 |
| `intent-too-many-items` | 502 | 列表超 3 项 |
| `intent-invalid-token` | 502 | 列表项不在白名单 |

响应形态与现有错误一致（`server.mjs:118`）：
```json
{ "error": { "code": "intent-missing-fields", "message": "..." } }
```

`violations` 数组写入 server 日志（**不进客户端响应**，避免泄漏字段细节）。

### 3.4 契约常量的来源（关键设计决策）

| 方案 | 优点 | 风险 |
|---|---|---|
| **A. 导入 `openaiProvider` 的 `ENUM_FIELDS`** | 单一事实源，永不漂移 | 该模块**冻结**，需导出常量 → **触碰冻结文件** |
| **B. validator 内独立声明** | 不碰冻结文件 | 可能与冻结源漂移 → **需静态一致性测试** |

**建议 B + 强制一致性测试**：
新建的 validator 文件不含任何冻结代码；
但必须有一个离线测试，**逐项比对** validator 的常量与
`openaiProvider.mjs` 中的定义完全一致。漂移即测试失败。

### 3.5 日志安全策略（强制）

**核心原则**：validator 的判定结果**只允许**把「规则级摘要」写入日志，
**绝不**写入原始模型输出或用户数据。

| 项 | 允许进日志 | 禁止进日志 |
|---|---|---|
| 机器可读 code | ✅ | — |
| 规则名（R2/R4b…）| ✅ | — |
| 违规**数量**统计 | ✅ | — |
| `violations[].detail` | ❌ | ✅ **禁止** |
| 字段的**实际值** | ❌ | ✅ **禁止** |
| 原始模型输出 / content | ❌ | ✅ **禁止** |
| 用户数据（文件名/图像/文本）| ❌ | ✅ **禁止** |

**理由**：`violations[].detail` 会包含 provider 返回的**实际字段值**
（如 `melancholy="huge"`、`atmosphere=["晴天"]`）。
这些值源自用户上传的图片内容，可能含个人信息。

**安全摘要形态**（由 `toLogSafeSummary()` 生成）：

```json
{
  "code": "intent-invalid-enum",
  "ruleCounts": { "R4b": 2, "R6": 1 },
  "violationCount": 3,
  "rulesTriggered": ["R4b", "R6"]
}
```

- ✅ 只含契约常量（字段名、规则名）与**计数**
- ❌ 不含任何来自用户数据的值

**客户端响应**同样只回 `code` + 通用 `message`，**不回传 violations**。

> ⚠ **当前 bridge 的 `[vision-debug]` 违反此策略**（`openaiProvider.mjs:158-162`
> 直接打印上游响应前 200 字符）。接入 validator 前应先处理（MEA-08 / E15）。

| 项 | 结论 |
|---|---|
| Validator 必填清单 | **wire 22 个**（`buildSchema().required`），**不是** internal 的 25 个 |
